# Hyprial GUI UI 变更交接模板

文档版本：2026-10-28

适用范围：产品、研发、AI agent 之间的界面变更交接

配套规范：[GUI 设计与研发规范](ui-development-standard.zh-CN.md) · [组件目录](component-catalog.zh-CN.md)

使用方式：复制本模板到 PR 正文或团队指定的任务记录中；需要在仓库内新增记录目录时，应在对应 PR 中明确创建路径，不假设仓库已有专用目录。不要把占位符当作已完成事实；不知道的内容如实写 UNKNOWN，不能留空冒充通过。

一条变更只写一个主 Change ID，子项追加 `-01`、`-02`。产品和研发共用同一记录，不各写一份互相矛盾的说明。

## 1. 基本信息

| 字段 | 填写 |
| --- | --- |
| Change ID | `<DEV-UI-xxx / Vxx-UI-xxx / 任务编号>` |
| 状态 | `DRAFT / READY FOR REVIEW / BLOCKED / ACCEPTED (visual) / DONE` |
| 产品 owner | `<姓名/角色>` |
| 研发 owner | `<姓名/角色/agent>` |
| 平台 | `shared / web / desktop / mobile` |
| 页面/组件 | `<页面名与源码路径>` |
| 目标分支 | `<branch>` |
| 基线 head | `<精确 SHA>` |
| Applicable-Decision | `<ADR-GUI-00x / 决策文件名与版本>` |
| 关联任务/PR | `<链接或编号>` |
| 原型/设计来源 | `<vendor 原件 hash、设计稿链接或“无”>` |

状态含义：

- `DRAFT`：方案或实现未完成，不得作为交付。
- `READY FOR REVIEW`：实现与自测完成，等待独立审核。
- `BLOCKED`：存在具体阻塞；写明阻塞点和下一执行人。
- `ACCEPTED (visual)`：产品接受视觉/交互，不等于真实业务通过。
- `DONE`：实现、适用验证、产品接受和必要合入均完成；缺一项不能标 DONE。

- [ ] 适配器/服务端不返回或回显 secret。
- [ ] 诊断信息已脱敏。
- [ ] 未读取或提交真实凭据到任务记录。

## 6. 验证记录

只运行适用于本次变更的检查；不要为纯文档任务跑完整构建。实际跑过的命令和结果必须照抄，失败也照抄。

| 检查 | 命令/操作 | 结果 | 覆盖范围 |
| --- | --- | --- | --- |
| 类型检查 | `cd gui && npm run typecheck` | `<PASS/FAIL/UNKNOWN>` | |
| 单元/组件测试 | `cd gui && npm test -- tests/<file>` | `<N passed>` | |
| 全量 GUI 测试 | `cd gui && npm test` | `<N passed>` | 仅 GUI |
| 构建 | `cd gui && npm run build` | `<PASS/FAIL/UNKNOWN>` | 静态构建 |
| 浏览器/交互 | `<URL、宽度、步骤>` | `<PASS/FAIL/UNKNOWN>` | |
| 键盘/读屏 | `<工具与步骤>` | `<PASS/FAIL/UNKNOWN>` | |
| 原生壳/真机 | `<设备/版本/路径>` | `<PASS/FAIL/UNKNOWN>` | |
| 真实后端 | `<登录/模型/Squire/聊天>` | `<PASS/FAIL/BLOCKED/UNKNOWN>` | |

验收分层必须写清楚：

- `fixture build`：只证明演示界面可构建。
- `placeholder call`：只证明请求到达占位服务并返回明确未实现。
- `real backend`：证明真实登录/模型/Squire/聊天/历史。
- `native package`：证明安装、启动、生命周期和平台 WebView。
- `mobile real auth`：证明 App 内入网、正式认证、远端会话；模拟器/direct-test 不能替代。

任一上层未做，相应状态写 NOT_RUN/BLOCKED/UNKNOWN。

## 8. PR 与声明

提交前：

- [ ] 仅本任务相关文件变化；未顺带修改产品实现、CI、依赖、服务或凭据。
- [ ] 相对链接可解析；示例参数与真实源码一致。
- [ ] `git diff --check` 通过。
- [ ] 新 head 上的验证证据已更新；旧 head 的结果不能沿用。
- [ ] PR 目标分支符合任务派单；不自行合入 `dev`。

PR 正文至少包含：

```text
Submitted-by: agent:<真实的发起 agent URI>

## 动机
<...>

## 改动
<...>

## 验证
<实际命令与结果>

## 当前限制与未验证项
<UNKNOWN/BLOCKED；fixture/real 区分>

Contract-Impact: <none / 说明；改变已发布字段语义时同步 contract/>
Skill-Impact: <none / 说明；改变 agent 操作方式时同步 skill/>
```

要求：

- `Submitted-by` 首行写发起本次 PR 的真实 agent URI，不冒用审查者或他人身份。
- `Contract-Impact`、`Skill-Impact` 必须如实；不能用 `none` 掩盖接口或操作方式变化。
- 不包含 token、密钥、邀请材料、私有日志、个人绝对路径或本机用户名。
- `dev` 合入由独立 verifier 完成；研发不代审、不代合、不改保护。

## 9. 最终检查清单

- [ ] 页面只使用已存在或有明确设计来源的组件、token、断点。
- [ ] 未把“有组件/有测试”写成“已上线”。
- [ ] 未把 fixture/占位/模拟写成真实登录、连接、发送或回复。
- [ ] loading/empty/error/unknown/权限态均有明确语义。
- [ ] 键盘、焦点、标签、错误关联、减少动画已检查或标 UNKNOWN。
- [ ] 凭据不落盘、不回显、不记录。
- [ ] 响应式与长文本经过实际检查或标 UNKNOWN。
- [ ] 产品接受、DEV-UI 登记和剩余缺口已记录。
- [ ] 验证命令、精确 head、结果和覆盖范围可复核。
- [ ] PR 声明完整，未自行合入 `dev`。

完成以上项目不等于自动通过 dev 审核；独立审核者仍需按精确 head 复核。
