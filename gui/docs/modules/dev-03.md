# 开发模块 03：飞书连接（J4）

> 历史模块设计与场景记录，保留当时的说明。当前页面、术语和后端接线请查 [统一方法对账](../../../docs/design/gui-v0.1-method-plan-2026-11-13.md)，不按本文旧状态表继续补方法。

开发预览用 `#j4=ready`、`#j4=authorize-failure`、`#j4=unavailable` 切换场景。正式包不含这些入口。

## 用户旅程

1. 连接页消息区显示“添加连接”入口。
2. 选择消息平台“飞书”。
3. 选择要绑定的 Agent，默认 Squire。
4. 完成本地授权。
5. 结果页显示“已连接”与绑定的 Agent。
6. 连接后聊天页出现“应用内 / 用飞书沟通”开关；未连接时不出现。

第 1–3 步可以返回上一步。授权成功后不再提供返回，避免把已生效的连接退回未连接。

## 状态与数据

会话是唯一事实来源。

- `messageConnection`：`not-connected` 或 `connected`，表示是否已绑定消息服务。
- `messageConnectionAgentId`：绑定到哪个 Agent。
- `chatChannel`：`in-app` 或 `feishu`，只在连接后生效。
- `flowScenarios.feishu`：`ready`、`authorize-failure`、`unavailable`，只由开发预览设置。

授权成功时写入连接与绑定 Agent。授权失败只显示失败，不改连接。清除绑定或场景为 `unavailable` 时，连接回到未连接、绑定 Agent 清空、沟通方式回到应用内。

连接状态投影到两处：连接页消息区，以及 Agent 的渠道服务字段。两处都从 `messageConnection` 读取，不保存第二份状态。

聊天可用性由会话投影：Agent 的模型服务已连接时可发送消息；没有会话时沿用既有 fixture 行为。

## 组件

- `src/features/connections/impl/message-connection-view-model.ts`：文案与投影。
- `src/features/connections/impl/MessageConnectionSection.tsx`：入口、四步流程、结果与失败重试。
- `src/features/chat/impl/ChatChannelSwitch.tsx`：连接后的沟通方式开关。

## 交互细节

- 授权失败停在授权步，显示“授权未完成。请重新授权。”，并提供“重新授权”。
- 接口不可用时显示暂不可用说明，不提供授权按钮。
- 聊天页输入草稿在“应用内 → 用飞书沟通 → 应用内”往返后保持不变，消息条数不变。
- 渠道开关位于消息列表上方，窄矮视口下不被输入区遮挡。

## 短矮视口的聊天可达性

同一环境下，基线 `66d18aaa`、模型服务管理提交 `c0eb043c7`、本旅程初版 `26d5063c7` 都会在 375×320 等短矮视口复现同一个缺陷：聊天页的单列网格把会话区压到 46 像素，消息区与输入区溢出覆盖信息面板，信息面板里的“管理 Agent”无法点击。

该缺陷在 `66d18aaa` 已存在，不是本旅程引入。

本旅程只增加一条短矮视口网格规则（`max-width: 979px` 且 `max-height: 430px` 时按内容分配行高），恢复信息面板的可达性。高视口（如 375×900、760×900）不命中该规则，会话区仍按原样在内部滚动，外层不新增滚动；本旅程的行为范围不因此扩大。

## 边界

- 不发起任何网络请求，授权是本地模拟。
- 不读写 `localStorage`、`sessionStorage`、IndexedDB 或 Cookie。
- 正式包只显示“未连接”或“暂不可用”，不出现开发场景词。
- J4 浏览器合同已纳入 `npm run verify`。正式模式从“开始”经“设置 → 打开首次设置”进入“账号与设备”；账号服务不可达时不得出现“用飞书沟通”或“已连接”。

## J3 聊天回归数据与页脚索引

J1 为默认 simulate 时，J3 下拉选择非基线本地场景会直接进入完成首次设置后的界面，避免默认连续会话或首次设置挡住聊天回归；显式选择的 J1 失败场景仍进入对应首次设置流程。契约场景沿用既有完成首次设置的入口。每次切换重新创建该场景的数据源与控制器；组织数据开启时也保留显式选择的 J3 数据。

- M-06：空历史，模型未连接，不可发送。
- M-07：一条失败的本地用户消息「请帮我检查模型连接。」，可通过既有重试入口重试；本场景仍模拟发送失败。
- M-08：显式空历史，可发送。与“没有聊天对象”的契约空数据场景不同。
- M-23：用户请求整理安排与助手完成回复，共两条历史。
- 聊天契约成功：两条已完成交流；新发送成功后由模拟 host 的历史返回用户消息及确定性助手回复。界面不根据接收成功自行生成回复。
- 聊天契约空数据：无聊天对象；读取错误与未配置分别返回不同错误，不回退到本地聊天。
- 聊天契约明确失败：两条发送前检查交流；新发送明确拒绝，保留草稿，不增加已发送消息或助手回复。
- 聊天契约未知：一条已接收但响应丢失的用户消息，恢复原请求的未知状态。只能查询、确认原幂等键；不自动重发、不生成助手回复。

此前成功、失败、未知契约共享一条欢迎消息，未体现不同历史；M-06/07/08 只设置发送模式，继承空的基线历史，M-07 因而缺少可重试的失败消息。

页脚 dev-01 至 dev-06 是静态开发模块索引，按原实现统一标注「暂不可用」，不是连接或服务健康检查。dev-03 的标签不代表聊天后端、飞书或真实 Agent 已接通；顶部本地测试数据说明持续显示。正式入口仍使用同一展示组件，并保持各能力现有不可用边界。
