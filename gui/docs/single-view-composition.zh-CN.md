# 预览与正式页面共用规范

基线：`intg/gui-init` / `fd7f4ea2770875873cb6602c633df3fdc73a8e61`。

产品页面只维护一套组件、布局、样式和校验。开发预览可增加页面外工具栏，通过注入能力与数据控制成功、失败、处理中和不可用场景；不再维护仅供预览的产品表单。

## 首次使用：本批迁移

入口链路：`main.tsx → App → AppShell → FirstRunPage → FirstRunOnboarding`。
开发入口 `DevPreviewApp` 使用同一条产品链路，仅提供模拟会话与场景。

- `features/onboarding/`：V17 首次使用组件及 controller；登录跳转官方授权页，不让用户填写账号访问令牌。
- `app/capabilities.tsx`：统一能力注入；设置页和首次设置从同一 provider 获取账号／模型能力。
- `platform/auth/`：真实 Web／原生账号适配，保留取消 ACK 和迟到结果防护。
- `dev/first-run-capabilities.ts`：只提供模拟结果；不请求真实服务、不保存 Key、不启动进程。
- `dev-mode/FixtureFirstRunPage.tsx`：删除。预览不得再以此类独立页面替换产品组件。

模拟首次对话确认后，只把草稿交给聊天页，不自动发送，也不生成模拟回复来宣告真实聊天完成。演示场景完成标记只在开发会话内生效。

正式账号、设备、模型凭据、Squire 启动、真实回复各自报告状态。不能合为“已连接”；模拟模式必须持续标识，不可用能力不得用假成功补齐。

## 后续迁移清单（不是已完成声明）

| 页面 | 当前情况 | 后续动作 |
| --- | --- | --- |
| 首次使用 | 本批改为共享 V17 页面 | 对开发／正式主入口做回归 |

| 飞书连接 | 真实侧与演示侧状态编排不同 | 逐项核对组件与能力适配，不以文件名判断重复 |
| 组织／Agent／机器 | 以各线视图模型组合 | 不覆盖其他负责人新功能；先核引用和状态语义，再迁移重复视图 |

`live` 容器与模拟适配器并存不等于两套 GUI。重复的产品 DOM／样式才是需要消除的部分。

## 给产品瑞华的同步

本批用已实现的 V17 账号与设备页替换旧预览“账号＋访问令牌”表单。模型步骤默认 Pi＋DeepSeek Key，使用“保存并继续”；Squire 按创建、凭据授权、启动分步展示。首次对话演示为草稿跳转，正式回复状态仍需真实服务确认。

后续原型应围绕共享组件和 token 调整；同时更新预览与正式页面，不再单独维护预览 HTML／表单。交接应注明修改组件、状态、截图、能力未接入项及对应提交，沿用 `ui-change-handoff-template.zh-CN.md`。
