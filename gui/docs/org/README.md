## 编写原则

- **功能有来源。** 只收三类功能：`dev` 上已实现的、在途规划中的（已有设计文档或分支）、用户明确要求的。不自行新增。
- **缺口分两种处理。** 缺口是用户要求了，但既未实现、也没有规划的部分（PRD 第 11 节）。
  - 部门与结构配置、改名：姚升悦决定先在 GUI 中设计，未接通时显示“暂不可用”。
  - 其余缺口：只显示“暂不可用（未立项）”。
- **标注后端状态。** 每条后端现状都注明来源（源码路径或分支@提交），并区分〔已实现〕〔在途〕〔缺口〕〔待确认〕。
- **未接通不显示成功。** 未接通的功能只显示“未连接”“状态未确认”“暂不可用”（任务登记第 3 节）。
- **跨 tab 直接改，共享文件按规范。**
  - 组织相关交互不论在哪个 tab，都由 dev-04 按交互设计修改，之后由用户旅程线合并（2026-10-29 群聊约定）。
  - 集成人负责的文件（壳层、开发定位层、热点文件）按任务登记不改，写成接口提案。例外：开发定位层的“组织数据”下拉由姚升悦 2026-10-30 决定接入（交互设计 13.2）。
