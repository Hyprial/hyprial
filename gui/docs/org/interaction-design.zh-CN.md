## 1. 设计原则

1. **组织是上下文，不是孤岛。** 组织本身的查看和管理放在“组织”tab。新建 Agent、迁移 Agent、发消息等动作在原处完成，并带上组织信息，不让用户跳到组织页去做。
2. **零个或多个工作组织。** 用户可以不属于任何组织（B2）；没有组织是合法、常见的起始状态，界面显示空状态与引导动作，不虚构常驻的默认组织。组织列表中的组织都是工作组织，按名称排序，当前组织带勾。
3. **当前组织是默认目标，不是筛选器。** 切换当前组织只影响两件事：组织类操作的默认对象，以及新建 Agent 的默认归属（B3）。它不改变通信判定，也不影响正在运行的 Agent。界面必须把这一点说清楚。
4. **不显示假成功。**
   - 后端未接通时，页面只显示“未连接”“状态未确认”“暂不可用”，以及本文新增的“依赖项状态未确认”（第 11 节）。
   - 未接通的组织动作不发远端请求，只在本地显示“暂不可用”（任务登记第 3 节、第 7 节待办）。
5. **权威不在浏览器。** 成员以 Casdoor 为准，组织文件以 OrgFS 为准，通信判定和迁移状态以 daemon 为准（B6）。权限由后端返回，GUI 只据此决定按钮是否显示，不在本地推断。
6. **写操作要能看清后果。** 移除成员、离开或删除组织、改名、发布配置、迁移 Agent，都先展示预览，再确认，不因网络超时自动重试。
7. **凭据当作秘密处理。** 邀请链接、短链接、加入命令都是凭据：
   - 输入时用密码框，提交后清空。
   - 不写入本地存储、URL 或日志。
   - 展示时提示“只私发给被邀请人”。
8. **缺口不伪装。** 没有决定先行设计的缺口，只占位显示“暂不可用（未立项）”，不画可操作的控件。

## 2. 交互深度与菜单层级

| 级别 | 含义 | 典型形态 | 规则 |
| --- | --- | --- | --- |
| L0 | 壳层常驻，任何 tab 都可见 | 左栏组织切换器、提醒角标 | 只放高频、全局的入口；点击后最多打开一个菜单 |
| L1 | tab 的页面主体，打开即见 | 页头、卡片、列表、内联短表单、分段切换 | 首屏回答“现在是什么状态” |
| L2 | 同一 tab 内下钻，不离开当前 tab | 子页签、详情侧栏 | 查看类功能最深到 L2 |
| L3 | 模态，完成或取消后才返回 | 对话框、多步向导、编辑器 | 创建、编辑提交、展示凭据、危险操作、多步流程都在这一级 |

菜单层级：

- 一级菜单是左栏的 tab 和账号菜单，都不新增项。
- 二级菜单是组织 tab 的 8 个子页签。
- 不设三级菜单。子页签内的分组用 L1 分段切换，详情用侧栏或对话框。
- 路径最长为“tab → 子页签 → 侧栏 → 对话框”。
- 对话框里不再打开对话框。
  - 需要确认的多步操作，在同一个 L3 容器内切换到确认步骤。
  - 从一个 L3 进入下一个 L3 时（例如模板向导进入编辑器），先关闭前一个，再打开后一个，不叠加。
- 关闭对话框后，焦点回到最初触发它的控件（UI 规范：焦点进入、离开与恢复）。

## 4. 壳层（全局）

### 4.1 组织切换器（F01）

**位置**：

- 目标位置：左栏品牌“Hyprial OS”下方。左栏收起时和窄屏下，移到页头左侧。
- 本版位置：不改壳层，切换器先放在组织 tab 页头；挂到左栏写成接口提案，交给集成人（见 13.2）。下面描述的显示内容与切换逻辑，两个位置相同。

**收起时显示**：

- 当前组织名（组织均为工作组织）。
- 没有当前组织时显示“未设置当前组织”。这时组织类操作的默认对象由后端决定：只有一个组织就用它，否则报 `ORG_REQUIRED` 并列出候选（#2078 第 4 节）。
- 状态未确认时显示“组织状态未确认”。

**展开菜单**（L0 菜单，不是模态）：

1. 工作组织，按名称排序，当前组织带勾。
   - 非 active 的组织显示状态标签：“创建未完成”（`creating`、`partial`）、“同步异常”（规划中的 `sync-problem`）。
   - 已离开的组织不出现在菜单中。
2. 分隔线后：“新建组织”“加入组织”“待处理邀请（n）”。

**切换逻辑**：

1. 点击某个组织后，发起“设置当前组织”请求。菜单关闭，切换器显示“切换中”。
2. 成功后，切换器显示新组织，并轻提示：“当前组织已改为 X。之后新建的 Agent 默认归入 X；通信与运行中的 Agent 不受影响。”
3. 失败时，保持原组织，显示后端给出的原因，不自动重试。某个状态的组织能否设为当前组织，以后端返回为准，GUI 不自行禁止。
4. 当前组织是 home 级设置，CLI 与 GUI 共用。CLI 改了当前组织，GUI 收到 `org.current.changed` 后刷新；收不到事件时，切换器每次打开都重新读取。

**未接通时**：

- 切换器显示“组织状态未确认”，菜单中不显示示例组织。
- “新建组织”“加入组织”可以打开，提交后只在本地显示“暂不可用”，不发请求。

### 4.2 待处理提醒（F06、F17）

- **组织邀请**：组织 tab 右侧的数字角标、切换器的“待处理邀请（n）”、开始页的提醒卡，点击都进入组织 tab → 邀请 → 我收到的邀请。
- **迁入请求**：这台电脑是迁移的目标机器时，开始页显示提醒卡“有 n 个迁入请求等待处理”，机器子页签也显示角标。点击进入组织 tab → 机器 →“这台电脑”侧栏 → 迁入请求（P13）。
- 数字只来自后端。没有数据时不显示角标；不能显示 0 来冒充“已确认没有”。

### 4.3 组织变化后的刷新（F20）

- **目标**：后端通过 daemon request 公共契约推送下列事件（#2078 第 7 节，目标 0.5.5.3）：
  - `org.current.changed`
  - `org.invite.pending`
  - `org.member.changed`
  - `org.agent.membership.changed`
  - `org.device.reachability`
  - `org.admission.refused`
- **收到事件后**：只刷新受影响的区块，并在区块右上角显示“更新于 hh:mm”。
- **数据来源**：读到的数据可能只是本机副本，不一定是组织空间的当前状态。例如设备记录（hyprial-cli-developer 2026-10-29 实测）。界面只写“更新于 hh:mm”，不写“最新”或“全网”。
- **事件通道未接通时**：
  - 每个列表区块提供“刷新”按钮。
  - 不按时间自动轮询写操作。
  - 不在本地根据“邀请已接受”推断“成员已出现”。

## 5. 组织 tab

### 5.1 页面结构

- **页头（L1）**：
  - 组织名，作为 h1（一页一个 h1），只作纯文本渲染。
  - 类型标签、我的角色（所有者或成员）、状态标签。
  - “设为当前组织”按钮。已是当前组织时，显示“当前组织”标签，不显示按钮。
- **查看哪个组织**：默认展示当前组织。页头组织名旁的下拉可以临时查看其他组织，不改变当前组织。这是视图选择，不叫“当前组织”。
- **子页签（L2）**：
  - 概览｜成员｜邀请｜机器｜拓扑｜统计｜文件｜设置。
  - 因角色不可用的页签显示为禁用并说明原因，不直接隐藏（见第 6 节）。
  - 宽度不足时横向滚动；窄屏改为下拉选择（第 12 节）。

### 5.2 概览（F03）

概览按“当前查看的组织”显示，区分两种情况：

| 情况 | 显示 |
| --- | --- |
| 没有任何可读的组织 | 读取失败或未接通时显示“状态未确认”。后端明确返回没有任何组织（`orgs: []`）时，显示空状态“还没有可用的组织。”和两个动作：“新建组织”“用邀请链接加入” |
| 工作组织，成员只有自己 | 正常显示概览，成员计数为 1。所有者另外看到“邀请成员” |

概览内容：

- **计数卡**：成员、Agent、机器，点击跳到对应子页签。没有数据时显示“状态未确认”。
- **我的角色与可做的事**：例如“你是所有者：可以邀请和移除成员，设置组织配置”；“你是成员：可以查看成员、机器和组织文件”。
- **组织状态**：创建未完成（`creating`、`partial`）时显示警告条。所有者看到“修复”，点击后打开 L3 对话框，先预览，再确认执行（P03）。
- **快捷动作**：
  - “邀请成员”：只在我是所有者时显示（第 6 节）。
  - “在此组织新建 Agent”。
  - “设为当前组织”。

### 5.3 成员（F05、F08、F09、F10）

分段切换（L1）：人｜Agent。没有“待审批”分段（审批没有数据源，不渲染）。

**人**：

- 列表显示显示名、账号、角色、来源（Casdoor）、同步状态。
- 点击打开成员侧栏（L2），内容包括：
  - 基本信息。
  - 该成员在本组织的机器与 Agent。
  - “发消息”：跳到聊天 tab 并选中该成员，只是导航，不新增后端能力。
  - “移除成员”：只对所有者显示，L3，见 P16。

**Agent**：

- 列表显示名称、主人、所在机器、运行状态。
- 点击打开 Agent 侧栏（L2）：所属组织列表、“发消息”、“在 Agent 页打开”。
- 列表上方“在此组织新建”：跳到 Agent tab 的新建表单，并预选本组织。

**待审批**：不提供（待决 3、Q06 未定；不渲染分段，也不写说明）。

**空状态**：

- 人只有自己时：“还没有其他成员。”所有者另外看到“邀请成员”。
- 没有 Agent 时：“这个组织还没有 Agent。”

### 5.4 邀请（F04、F06、F07）

分段切换（L1）：发出邀请｜我收到的邀请｜用邀请链接加入。

**发出邀请**（只在工作组织中对所有者显示）：

1. 输入成员账号，点“生成邀请”。
2. 成功后打开 L3 结果对话框，内容如下：
   - 邀请链接，主形式为 `https://hyprial.ai/join#…`。
   - 有效期 1 小时，显示到期时间。
   - 短链接：在途功能。没有短链接时不显示该行，长链接照常可用。
   - 按钮：“复制邀请链接”“复制加入命令”。
   - 固定提示：“邀请链接含连接凭据，只私发给被邀请人，不要贴到群里。”
3. 复制后只提示“已复制”，不说“邀请已送达”。
4. 关闭对话框后，链接不再显示，也不保存。需要时重新生成。

**我收到的邀请**（领取邀请）：

- 列表内容：在网页上已接受、但本机还没有加入的邀请。每条显示组织名、邀请人、接受时间。
- “加入”：打开 L3 确认，写明加入后的影响：“加入后，组织成员可以和你的 Agent 通信，前提是组织配置允许。”
- “拒绝”：对应 #2078 规划的 `declined`，后端支持前不显示。
- 逐条处理，不把“全部接受”作为默认动作。CLI 的 `--accept-all` 只在 CLI 中显式使用。
- 每条的结果：
  - 已加入。
  - 未加入，附原因。
  - 已跳过：本机已在该组织，或曾主动离开该组织。曾主动离开的组织要用邀请链接重新加入。

**用邀请链接加入**：

1. 在密码框中粘贴邀请链接，点“加入”，输入框立即清空。
2. 显示四步进度：连接邀请人 → 加入组织 → 注册设备 → 连接成员。最长约 75 秒；超时显示“加入未完成”和原因。
3. 输入框接受邀请的四种写法，界面统一称“邀请链接”。

### 5.5 机器（F12、F17 目标方）

- **列表**：沿用 J6 的机器列表，显示主机名、“这台电脑”、连接状态、系统、加入时间。
- **连接状态**：
  - 现有后端提供三种：“在线”“状态未知”“同步中”。“同步中”表示目录行还没有到达本机，不是待审批，所以不提供“批准”按钮。
  - #2078 规划另增“离线”“休眠”。休眠是重试预算用完，附失败次数和最后尝试时间。
- **立即重试**：休眠的机器显示“立即重试”（L1 按钮，不需要模态）；离线的机器不显示。
- **不提供移除机器**，与 J6 一致。
- **“这台电脑”侧栏（L2）**：
  - 显示本机信息。
  - 本机是迁移目标时，显示“迁入请求”列表。每条显示迁移单编号、来源 Agent、源机器、发起时间、状态。
  - 点击一条迁入请求，打开迁移单（L3，见 P13）。
- **第二台电脑**：加入过程见 P08。

### 5.6 拓扑（F13）

- 沿用 J7：结构视图与通信视图切换，选择节点，选择边打开 Inspect 侧栏。
- **结构视图**：数据来自已采信的组织配置，包括部门与汇报关系（后端支持后）、业务线、常驻角色。
- **通信视图**：边分两层，用不同图例显示，不合并成一个“可以通信”的结论：
  - 路由约定：组织配置中的 `routing`，是静态约定。
  - link：发送方持有指向接收方的 link 才能发送，边带方向。
- **link 数据来源**：link 表落到 OrgFS（WP2）还在途。WP2 可用前，通信层只显示本机 Agent 持有的 link，并注明“只含本机 Agent 的链接”。

### 5.7 统计（F14）

- **时间窗口**：近 1 天、7 天、30 天，与在途的 `org network inspect --window` 一致。
- **视图**：每小时消息量折线、关系 Top 10、参与者表（发出、收到）。
- **视角**：本机可见范围，或某个 Agent。选中 Agent 后只显示与它相连的边。
- **范围说明**（必须显示）：“只统计本机能看到的通信；没有数据不代表没有活动。”
- **按任务统计**：不显示（缺口，Q08）。
- **未接通时**：显示“暂不可用”，不显示示例图表。

### 5.8 文件（F16，OrgFS）

**结构**：

- 分段切换（L1）：文件｜回收站。
- 先选择空间，再看目录树和预览（L2）。
- 每个文件显示最后修改人、时间、版本。
- 固定提示：“组织文件对组织网络内可读，不要存放秘密。”

**子操作**：

| 子操作 | 本期是否呈现 | 入口与深度 | 权限 |
| --- | --- | --- | --- |
| 浏览、预览 | 呈现 | 文件 → 目录树（L2） | 成员 |
| 编辑、保存 | 呈现 | 预览 →“编辑”（L3 编辑器）。保存后以后端返回的新版本为准，显示“已保存（版本 n）”。冲突时显示双方差异，用户选择后重新保存，不静默覆盖 | 有写权限的成员 |
| 新建文件、新建文件夹 | 呈现 | 目录树“新建”（L3） | 有写权限的成员 |
| 移动、重命名 | 呈现 | 行菜单“移动”（L3） | 有写权限的成员 |
| 删除 | 呈现 | 行菜单“删除”（L3 确认），文件进入回收站 | 有写权限的成员 |
| 回收站、恢复 | 呈现 | 回收站 → 选择文件 →“恢复”（L3 确认），恢复到原路径 | 有写权限的成员 |
| 彻底清除 | 不提供 | 没有入口（daemon 没有条目级清除；不把“清历史”说成“清回收站”） | — |
| 历史、按版本查看 | 不提供 | 没有入口（owner 2026-11-25 决定 OrgFS 不做历史） | — |
| 导入、导出 | 本期不呈现 | 用 CLI `hyprial fs import/export` | — |
| 监听变化 | 不单独呈现 | 只用于刷新列表 | — |
| 空间成员管理 | 不呈现 | 组织成员在“成员”“邀请”中管理 | — |

**所选空间的状态**：按所选空间的反馈显示，不把一种情况套到所有空间：

| 情况 | 显示 | 可用操作 |
| --- | --- | --- |
| 没有组织数据源 | 没有组织入口，不渲染 | 无，不发请求 |
| 所选空间的健康状态未知 | “状态未确认” | “刷新”；写操作禁用并说明原因 |
| 后端确认该空间的历史层异常（例如 2026-10-29 实测的 `group-internal`：内容完整，历史为空） | “依赖项状态未确认：该空间的历史记录异常，等待空间所有者修复” | 只能预览内容。编辑、新建、移动、删除、恢复、彻底清除全部禁用，并说明原因 |
| 正常 | 正常显示 | 按权限 |

### 5.9 设置（F15、F19）

设置页按动作区分权限，不用组织角色统一控制整页：

| 动作 | 谁可以操作 |
| --- | --- |
| 模板导入、编辑与发布配置候选、改名、删除组织 | 只有所有者（姚升悦决定：组织所有者设置配置） |
| 采信配置候选 | 本节点 owner，按本节点权限判断，与组织角色无关 |
| 离开组织 | 成员；authority 设备不能直接离开 |
| 查看各区块 | 所有成员 |

**基础信息**：

- 显示组织名、类型、状态、所有者、我的角色。
- “改名”（工作组织，所有者）：
  1. 打开 L3 对话框，输入新名称。就地校验，规则与新建组织相同。
  2. 对话框说明影响：“改名后，成员的组织列表和切换器都会显示新名称。”
  3. 确认后显示“已提交，等待处理”；刷新后显示新名称。
- 改名是基础设置，按姚升悦决定先在 GUI 中设计，按设计完整交互。改的是显示名还是组织标识，在后端对齐时确定。未接通时，提交只在本地显示“暂不可用”。

**结构与部门**：

- **成员看到的内容**：只读展示已采信的配置：
  - 部门与汇报关系：部门名称、负责人、上级部门、成员（人和 Agent）。字段在后端对齐时确定。
  - 业务线：负责人、协调人、看板、代码仓库。
  - 成员档案。
  - 常驻角色：节点、角色、服务对象。
- **所有者，还没有设置结构时**：显示“还没有设置组织结构。”和两个动作：“从模板导入”（主按钮）、“从空白开始”。
- **所有者，已有配置时**：显示“编辑”“从模板导入”。
- **从模板导入**（L3 向导，3 步）。不必从头编写配置：
  1. 选择来源。两种：
     - 内置模板：列表由后端提供，每个模板显示名称、说明、包含的部门数和角色数。
     - 上传配置文件：格式与组织配置导入一致。
  2. 预览：显示将导入的部门与汇报关系、业务线、常驻角色、通信路由、规范；与当前配置的差异；校验结果。
  3. 点“在编辑器中打开”：向导关闭，配置编辑器打开（P10），导入的内容已填好，可以继续修改。发布前不生效。
- **未接通时**：模板列表显示“状态未确认”；编辑器可以打开，但“发布”只在本地显示“暂不可用”。

**通信权限**：

- **准入规则说明**：双方至少共享一个组织，且该组织的配置允许（B5）。观察期内，违反规则的消息仍放行；强制期才拒绝（待决 4）。
- **路由约定**：展示 `routing` 的种类、对象、范围。范围按原文显示。所有者在配置编辑器中修改。
- **link 概况**：本机 Agent 持有的 link 数量、bypass 状态。逐个管理在 Agent 详情 → 通信（P11）。
- **“在拓扑中查看”**：跳到拓扑的通信视图。

**规范**：只读展示自主程度、升级路径、协作礼仪（`norms`）。所有者在配置编辑器中修改。

**版本**：

- 显示本节点已采信的版本（版本号、发布时间、发布者）、待采信的候选，以及候选与已采信版本的差异。
- 所有者看到“编辑”“从模板导入”。
- 本节点 owner 看到“采信”（L3 确认）。
- 发布后显示“已发布候选，等待采信”，不显示“已生效”。
- 候选所在的配置空间按 5.8 的空间状态显示。

**危险操作**（L3，见 P16）：

- 离开组织：对成员显示；authority 设备不能直接离开，按钮禁用并说明原因。
- 删除组织：只对所有者显示；只能在该组织的管理设备上完成，其他设备上 daemon 拒绝并说明到管理设备删除。

## 6. 角色与可见性

只分所有者和成员两级（姚升悦决定）。#2078 推荐由“管理员或所有者”审批，本设计按所有者处理。

| 动作 | 所有者 | 成员 | 非成员 |
| --- | --- | --- | --- |
| 查看概览、成员、机器、拓扑、统计、文件、设置 | 是 | 是 | 否 |
| 邀请成员（工作组织） | 是 | 否 | 否 |
| 移除成员 | 是，需在 authority 设备上执行 | 否 | 否 |
| 审批 Agent 加入工作组织 | 是 | 否 | 否 |
| 设置组织配置：模板导入、编辑、发布候选 | 是 | 否 | 否 |
| 改名（工作组织） | 是 | 否 | 否 |
| 写 OrgFS 文件、从回收站恢复 | 是 | 是，只读成员除外 | 否 |
| 彻底清除 OrgFS 文件 | 是 | 否 | 否 |
| 离开组织 | 不能，authority 设备不能直接离开 | 是 | — |
| 删除组织 | 是，需在 authority 设备上执行 | 否 | — |

说明：

- “采信组织配置”不是组织角色，而是每个节点 owner 对自己节点的操作。
- ACL 授权不放进 GUI，由后端在相关操作中连带处理（姚升悦决定）。
- 表中的“是/否”以后端返回的权限为准，GUI 只用它决定按钮是否显示。

## 7. Agent tab

**Agent 卡片**：

- 显示所属组织标签，最多 2 个，其余显示“+n”（#2078 第 7 节视图建议）。
- 增加“按组织筛选”，用来查看某个组织内可以联系的 Agent。

**新建 Agent（F11，L3 表单）**：

- “所属组织”下拉默认选当前组织；没有当前组织时默认“不加入组织”（B4：新建时未指定组织则归当前组织，没有当前组织时不加入任何工作组织）。
- 下拉包含“不加入组织”选项；Agent 的所属工作组织可以为空列表。
- 下拉下方说明：“默认归入当前组织 X。”

**Agent 详情 → 所属组织（F10，L2）**：

- 列出所属组织。
- “加入组织”：打开 L3 对话框选择工作组织；审批没有数据源，提交被拒绝时只发通知（`加入组织暂不可用。`），对话框不预先说明。
- “移出”：从所属工作组织列表中移出；支持移出最后一个组织，Agent 可以不属于任何工作组织。

**Agent 详情 → 通信（L2）**：

- **可以发送的对象**（本 Agent 持有的 link）：
  - 每行写明方向：本 Agent → 对端。另显示状态、在途数、最近使用时间。
  - “添加”：本 Agent 持有一条指向对端的 link，之后可以向对端发送。
  - “收回”：本 Agent 不能再向对端发送。对端能不能向本 Agent 发送不受影响，那取决于对端是否持有指向本 Agent 的 link。
  - 只列本 Agent 持有的 link，对端持有的 link 不在这里显示。
  - 添加和收回都由主人操作，需 L3 确认（P11）。
- **统计**：同 5.7，视角固定为该 Agent。
- **最近被拒的消息**（在途）：显示原因与修复入口。本 Agent 因没有 link 而发送失败时，修复入口是“添加可以发送的对象”。

**Agent 详情 → 迁移（F17，源端）**：见 P13。

## 8. 聊天 tab

现有三种不可发送原因保持不变：需要连接模型服务、需要启用 Agent、消息功能暂不可用。

新增发送被拒的提示（F18，L1 内联）。消息气泡下方显示原因，并给出修复入口（#2078 第 7 节视图建议）：

| 原因 | 提示 | 修复入口 |
| --- | --- | --- |
| 没有共同组织（`NO_SHARED_ORG`） | “你和 Y 没有共同组织。” | “把 Agent 加入 Y 所在的组织”：跳到 Agent 详情 → 所属组织，并预选组织。<br>“邀请 Y 加入组织”：只对所有者显示，跳到发出邀请，并预填账号 |
| 组织配置不允许（`ORG_POLICY_DENIED`） | “组织 X 的通信设置不允许这条消息。” | “查看 X 的通信权限”：跳到组织 tab → 设置 → 通信权限 |

- **观察期**（0.5.5.3，待决 4）：消息照常发送，同时提示“按新规则，这条消息将被拒绝”。
- **Agent 之间因没有 link 被拒的消息**：不在聊天中提示，在 Agent 详情 → 通信 → 最近被拒的消息中显示（第 7 节）。
- **未接通时**：不显示被拒提示，只沿用现有的三种原因。
- **修复之后**：跳转的目标页要预填对象。修复完成后，用户回到会话重新发送，不自动重发。

## 9. 开始页、首次设置、账号菜单

- **开始页**：
  - 有待处理邀请时，显示提醒卡“你有 n 条组织邀请”，点击进入组织 tab → 邀请 → 我收到的邀请。
  - 有迁入请求时，显示提醒卡“有 n 个迁入请求等待处理”，点击进入组织 tab → 机器 →“这台电脑”侧栏。
- **首次设置与登录**：登录完成后如有待处理邀请，逐条列出并让用户确认，不再静默全部接受（#2078 第 5 节 D6、验收 A2）。用户可以选“稍后处理”，之后从提醒卡进入。
- **账号菜单**：不新增组织入口。组织入口统一放在切换器和组织 tab。

## 10. 关键流程

每个流程写明入口、前置、步骤、结果、异常和未接通时的表现。第 16 节把它们串成用户旅程。

### P01 首次进入：没有组织

- **入口**：首次设置完成后进入主界面。
- **前置**：已登录；本机尚未加入任何工作组织（B2，`orgs: []` 合法，不创建默认组织）。
- **步骤**：
  1. 切换器显示“未设置当前组织”，菜单中没有任何组织条目。
  2. 组织 tab 概览显示空状态“还没有可用的组织。”和两个动作：“新建组织”“用邀请链接加入”（5.2）。
  3. 有待处理邀请时，开始页显示提醒卡。
- **未接通时**：
  - 切换器显示“组织状态未确认”。
  - 组织 tab 显示“状态未确认”，不显示示例组织。

### P02 切换当前组织

- **入口**：组织切换器；组织 tab 页头的“设为当前组织”。
- **步骤**：见 4.1 的切换逻辑。
- **结果**：之后新建 Agent 时，“所属组织”的默认值改为新组织。
- **异常**：后端拒绝时，保持原组织并显示原因。

### P03 新建组织

- **入口**：切换器“新建组织”；组织 tab 的引导卡或空状态。
- **步骤**：
  1. L3 对话框，填写组织名（必填）。就地校验规则（B1）：只用小写字母、数字和连字符，最长 57 个字符，不能以 `-acl` 结尾。
  2. 点“创建”。按钮显示“处理中…”，防止重复提交。
  3. 成功：关闭对话框，打开新组织的概览，并询问“是否设为当前组织”，不自动切换。
  4. 失败：对话框内显示原因，保留输入，可以重试。
- **创建未完成**（`creating`、`partial`）：
  - 概览显示“创建未完成”。
  - 所有者可以点“修复”，先预览，再确认执行。
  - 也可以用同一个名称重新创建。
- **未接通时**：提交后只在本地显示“暂不可用”，不发请求，也不创建本地组织。

### P04 邀请成员

- **入口**：组织 tab → 邀请 → 发出邀请；概览快捷动作。
- **前置**：查看的是工作组织，且我是所有者。
- **步骤**：
  1. 输入成员账号，点“生成邀请”。
  2. 成功后打开结果对话框（5.4）。
  3. 复制链接，私下发给对方。
- **结果**：对方加入后，成员列表要收到 `org.member.changed` 或用户手动刷新后，才出现新成员。
- **异常**：
  - 账号不存在、账号服务不可用、额度已满：就地显示原因，保留输入。
  - 没有权限：说明需要所有者权限。
- **未接通时**：提交后只在本地显示“暂不可用”。不出现结果对话框，不生成示例链接。

### P05 领取邀请（我收到的邀请）

- **入口**：组织 tab 角标；切换器“待处理邀请（n）”；开始页提醒卡；登录后的确认。
- **前置**：已在网页上接受邀请，本机还没有加入。
- **步骤**：
  1. 组织 tab → 邀请 → 我收到的邀请，逐条列出。
  2. 点“加入”，打开 L3 确认，写明加入后的影响；确认后显示“正在加入 X…”。
  3. 成功：该条显示“已加入 X”，切换器出现新组织，并提示“是否设为当前组织？”，不自动切换。
  4. 失败：该条显示“未加入：原因”，可以重试。
  5. 后端支持拒绝后：点“拒绝”，L3 确认后，该条标为已拒绝。
- **异常**：
  - 本机设备未就绪：提示先完成登录。
  - 本机已在该组织，或曾主动离开该组织：该条标为“已跳过”，并说明原因。
- **未接通时**：列表显示“状态未确认”，不显示示例邀请。

### P06 用邀请链接加入

- **入口**：切换器“加入组织”；组织 tab → 邀请 → 用邀请链接加入；引导卡。
- **步骤**：
  1. 在密码框中粘贴邀请链接，点“加入”。
  2. 输入框立即清空，显示四步进度。
  3. 成功：结果同 P05 第 3 步。
- **异常**：

  | 情况 | 下一步 |
  | --- | --- |
  | 邀请已过期（1 小时）、已被使用、无效、格式错误 | 提示“请邀请人重新发送” |
  | 邀请版本过旧 | 提示“请邀请人重新生成新版邀请” |
  | 已被移出该组织 | 说明原因，不提供重试 |
  | 超时 | 显示“加入未完成”，可以重试 |

- **未接通时**：提交后只在本地显示“暂不可用”，不发请求。

### P07 加入后刷新组织内的人、机器、Agent

- **触发**：P05 或 P06 成功。
- **步骤**：
  1. 组织 tab 打开新组织的概览，计数卡显示“同步中”。
  2. 收到成员、Agent、机器的变化事件后，计数和列表更新，并显示“更新于 hh:mm”。
  3. 用户随时可以点“刷新”。
- **规则**：
  - 同步完成前，除了“已加入”，不显示别的结论。
  - 不根据邀请状态推断成员已出现。
  - 不在本地创建机器记录（任务登记待办）。

### P08 第二台电脑接入已有组织（组织侧）

- **场景**：用户已是组织成员，在第二台电脑上登录。
- **组织侧**（任意成员的组织 tab → 机器）：
  1. 新机器出现，状态为“同步中”。
  2. 后端确认后，状态变为“在线”或“状态未知”。
  3. “这台电脑”只标在本机那一行。
- **第二台电脑上**：怎样列出“已是成员的组织”，取决于后端如何区分新邀请和已是成员的新设备（Q11）。确认前，沿用 P05 的列表与确认交互。
- **规则**：机器只来自后端的设备列表。
- **没有机器模型时**：不渲染 J6 机器区，显示通用的“状态未确认 + 刷新”。

### P09 Agent 与组织：新建、加入、移出、审批

- **新建**：Agent tab → 新建。“所属组织”默认为当前组织，提交（L3）。
- **加入**：Agent 详情 → 所属组织 → 加入组织 → 选择工作组织 → 提交。审批没有数据源，被拒绝时只发通知（`加入组织暂不可用。`）。所有者把自己的 Agent 加入自己的工作组织时，申请人和审批人是同一人。是否省掉审批这一步，以后端为准（Q06）。
- **移出**：Agent 详情 → 所属组织 → 某组织“移出” → L3 确认；支持移出最后一个组织，允许 Agent 所属工作组织为空列表。
- **未接通时**：
  - 表单可以填写，提交后只在本地显示“暂不可用”。
  - 详情中的所属组织显示“组织状态未确认”（J2 现状）。

### P10 设置组织配置：模板导入、编辑、发布与采信

- **入口**：
  - 组织 tab → 设置 → 结构与部门 →“从模板导入”或“从空白开始”。
  - 组织 tab → 设置 → 版本 →“编辑”。
- **前置**：我是所有者。采信由各节点 owner 在自己的节点上操作。
- **步骤**：
  1. 从模板导入时，先完成 5.9 的三步向导，然后进入编辑器。
  2. L3 配置编辑器按结构分区：部门与汇报关系、业务线、常驻角色、通信路由、规范。
  3. 点“校验”，显示结果：错误必须修正，警告可以继续。
  4. 点“发布候选”，显示“已发布候选，等待采信”。
  5. 本节点 owner 在版本区点“采信”（L3 确认）。新版本号必须大于当前版本。采信后，版本区显示新版本。
- **规则**：
  - 不显示“已生效”，是否采信由各节点 owner 决定。
  - 部门与汇报关系和其他配置一样，可以编辑和发布，按设计完整交互，不区分后端是否已经支持（姚升悦决定）。字段名在后端对齐时确定。
- **未接通时**：
  - 模板列表显示“状态未确认”。
  - 发布和采信只在本地显示“暂不可用”，不发请求。

### P11 管理 Agent 可以发送的对象（link）

- **入口**：
  - Agent 详情 → 通信 → 可以发送的对象。
  - Agent 详情 → 通信 → 最近被拒的消息 →“添加可以发送的对象”。
- **步骤**：
  1. 查看列表。每行显示“本 Agent → 对端”、状态、在途数、最近使用时间。
  2. “添加”：主人输入对端，L3 确认。确认框写明“添加后，本 Agent 可以向 Y 发送”。
  3. “收回”：主人在某一行点“收回”，L3 确认。确认框写明“收回后，本 Agent 不能再向 Y 发送；Y 能否向本 Agent 发送不受影响”。
- **规则**：
  - link 只管 Agent 之间的发送，方向是持有者到对端。
  - 组织准入（共享组织，加上组织配置）与 link 是两层判断，界面分开显示。
- **未接通时**：列表显示“状态未确认”；添加和收回只在本地显示“暂不可用”。

### P12 查看与编辑 OrgFS 内容

- **入口**：组织 tab → 文件。
- **步骤**：
  1. 选择空间，浏览目录，选择文件预览。
  2. 有写权限时点“编辑”，进入 L3 编辑器。
  3. 保存后显示“已保存（版本 n）”。
- **删除与恢复**：
  1. 行菜单“删除”，L3 确认后，文件进入回收站。
  2. 在回收站中选择文件，点“恢复”，L3 确认后恢复到原路径。
  3. 回收站只提供“恢复”；没有“彻底清除”入口。
- **冲突**：后端报告版本冲突时，显示双方差异，用户选择保留哪一份后重新保存，不静默覆盖。
- **空间状态**：按 5.8 的四种情况显示。
- **没有组织数据源时**：没有组织入口，不发请求。

### P13 把 Agent 迁移到组织内机器

**前置**：

- 现有后端：只能迁移到同一主人的机器。
- 规划（R4.2，未批准实施）：
  - 源与目标在同一组织、同一获准空间；跨组织拒绝。
  - 迁移后主人不变。
  - 目标方必须同意。

**迁移单的 7 项**：源端和目标端核对的是同一份计划，迁移单编号和版本一致。缺项显示“未知”、原因和责任方。

1. 主人证明。
2. 旧、新 URI 与机器变化。
3. harness 版本。
4. 凭据处置：随迁、需要重新认证或禁止携带。
5. 旧 URI 去向。
6. 回滚条件。
7. 预计停机。

**源端**（Agent 的主人，在源机器的 GUI 上）：

1. Agent 详情 →“迁移”，打开 L3 向导。
2. 选择目标机器：
   - 只列同组织的机器。
   - 只列属于自己的机器；他人的机器不出现，也不写说明（缺口）。
3. 检查：显示可迁移性检查的结果。
4. 核对计划：显示后端生成的迁移计划（编号、版本）和 7 项。源端核对后点“发起”。
5. 发起后生成迁移单，状态按后端返回显示，例如“等待目标方同意”。关闭向导后，在 Agent 详情 → 迁移中继续查看。

**目标端**（目标机器上有权接收的人，在目标机器的 GUI 上）：

1. 开始页提醒卡“有 n 个迁入请求等待处理”，或组织 tab → 机器 →“这台电脑”侧栏 → 迁入请求（L2）。
2. 打开迁移单（L3），显示迁移单编号与版本、来源 Agent、源机器，以及 7 项。
3. 点“同意”或“拒绝”后，在同一个对话框内切换到确认步骤并确认，不再打开新的对话框。处理完成后对话框关闭，焦点回到该条迁入请求。
4. 同 owner 时，目标方就是本人，在目标机器上处理。

**回到源端**：

- 源端 Agent 详情 → 迁移按后端返回显示迁移单状态：等待目标方、待验证、计划冲突、可以开始、已拒绝。收到事件或点“刷新”后更新，前端不自行推进状态。
- 只有后端返回“可以开始”时，“开始迁移”才可点，点击后进入进度。
- 计划冲突时，只能取消后重新发起，双方重新同意。

**目标方用 CLI 处理时**：

- 源端显示迁移单编号，并提示“请目标方在目标机器上处理这张迁移单”。
- 目标方处理后，源端点“刷新”。

**进度**：

- 源端在 Agent 详情中查看（L2）；目标端在迁入请求中点“查看进度”。
- 显示阶段、已传字节与文件数、速率、最近进展、重试原因。
- 不显示剩余时间估算。后端返回 ok 不等于迁移完成。

**结束**：

- 结束状态为完成、失败、已取消。
- 参与方在完成前都可以“取消”。
- “回滚”只在后端声明允许的阶段显示。

**规则**：迁移单不可变。要改条件，只能取消后重新发起，双方重新同意。

**目标端先发邀请**：R4.2 允许目标端先发出迁入邀请（意向状态 pending-source）。这一路径的 GUI 入口待 R4.2 定稿后补（Q18）。

**数据源没有实现迁移时**：源端向导入口和目标端同意/拒绝都不渲染，也不写说明。

### P14 查看统计

- **入口**：组织 tab → 统计；Agent 详情 → 通信 → 统计。
- **步骤**：
  1. 选择时间窗口。
  2. 选择视角：本机可见范围，或某个 Agent。
  3. 查看折线、Top 10 和参与者表。
- **规则**：始终显示数据范围说明；任务维度显示“暂不可用（未立项）”。
- **未接通时**：显示“暂不可用”，不显示示例图表。

### P15 通信被拒的提示与修复

- 提示与修复入口见第 8 节和第 7 节“最近被拒的消息”。
- 修复入口跳转后，目标页要预填对象。例如：邀请对话框预填账号，加入组织对话框预选组织，添加可以发送的对象时预填对端。

### P16 移除成员、离开组织、删除组织

**移除成员**（所有者）：

1. 成员侧栏 →“移除成员”，打开 L3 预览：受影响的设备、tailnet、authority 设备、断连影响。
2. 确认。
3. 如果后端报告预览已变化或版本冲突，重新展示最新预览，要求再次确认，不重用旧确认。

**离开组织**：

1. 设置 → 危险操作 →“离开组织”，打开 L3 预览。
2. 输入组织名确认。
3. authority 设备不能直接离开，界面说明原因。

**删除组织**（所有者）：

- 流程同离开：打开对话框时发一次未确认的 `org.delete` 取预览，展示受影响设备、管理设备与“删除后不能恢复”；输入组织名后点确认，带预览的 `operationId` 发确认（OC7 两步删除）。打开发一次预览请求；点确认发一次确认写入，随后刷新组织列表；确认失败后对话框自动再读一次预览，这是恢复读取，不是第二个用户动作。只有确认阶段为 `complete` 才提示已删除；预览已是 `complete`（别处已删完）同样按已删除关闭。
- 预览阶段不是“待确认”时（上次删除未完成），提示“上次删除尚未完成（阶段：…）；确认会继续完成”。
- 非管理设备上 daemon 以 `AUTHORITY_REQUIRED` 拒绝，界面说明只能在管理设备上删除；还有未删除的子组织时以 `OPERATION_CONFLICT` 拒绝并列出子组织。
- 确认请求失败或阶段不是 `complete` 时，删除可能已部分执行：界面刷新组织列表，提示再次删除并确认会继续完成；请求进行中不能关闭对话框。

**进度与结果**：

- 阶段依次为：待确认、待 authority 或 OrgFS 处理、待 tailnet 处理、完成。
- 提交后显示“已提交，等待处理”。列表收到事件或刷新后才更新，不在提交后立即从列表删除。

### P17 组织改名

- **入口**：组织 tab → 设置 → 基础信息 →“改名”（工作组织，所有者）。
- **步骤**：见 5.9 基础信息。
- **结果**：后端完成后，切换器、页头、成员的组织列表都显示新名称。
- **异常**：
  - 名称不合规：就地提示。
  - 后端拒绝：显示原因，保留输入。
- **未接通时**：提交后只在本地显示“暂不可用”，不发请求。

## 11. 状态与文案词表

| 状态 | 用途 | 文案 | 可用动作 |
| --- | --- | --- | --- |
| 暂不可用 | 功能未接通后端 | “X 暂不可用” | 无，或“了解原因” |
| 暂不可用（未立项） | 没有决定先行设计的缺口 | “X 暂不可用（未立项）” | 无 |
| 未连接 | 连接未建立（网络、服务） | “未连接” | “重试连接” |
| 状态未确认 | 数据读取失败，或状态未知 | “状态未确认” | “刷新” |
| 依赖项状态未确认 | 后端已确认某个依赖的子系统只部分可用，例如某个空间的历史层异常 | “依赖项状态未确认：原因” | 只保留不受影响的操作；不能当作“可用”呈现 |
| 加载中 | 正在读取 | 骨架屏，不写“成功” | — |
| 空 | 已确认没有数据 | 各区块的空状态句 | 对应的创建或邀请动作 |
| 处理中 | 写请求已发出 | “处理中…”，按钮禁用 | — |
| 已提交 | 后端已接收，结果未定 | “已提交，等待……” | “查看进度” |
| 失败 | 后端明确失败 | “X 未完成：原因” | “重试”，保留输入 |
| 完成 | 后端明确完成 | 只在后端返回完成时使用 | — |

组织、邀请、设备、Agent 归属、准入、迁移的业务状态取值，见 PRD 第 6 节。

文案规则：

- 未知、失败、空、忽略不共用同一句话。
- “已保存”“已连接”“已完成”不混用。
- 组织名只作纯文本渲染。

### 11.1 邀请相关文案：创建、领取、加入各用一套

任务登记要求这三类状态使用相互独立的文案：

| 阶段 | 进行中 | 成功 | 失败 |
| --- | --- | --- | --- |
| 创建邀请（所有者） | “正在生成邀请链接…” | “邀请链接已生成，1 小时内有效。只私发给被邀请人。” | “邀请链接未生成：原因” |
| 领取邀请（我收到的邀请） | “正在加入 X…” | “已加入 X” | “未加入 X：原因”；或“已跳过：原因” |
| 用邀请链接加入 | 四步进度：连接邀请人 → 加入组织 → 注册设备 → 连接成员 | “已加入 X” | “加入未完成：原因”，附下一步 |

叫法与使用规则：

- 统一称“邀请链接”，不再用“邀请码”。
- 动作统一称“加入”。
- 成功句只在后端返回成功时使用。未接通时一律显示“暂不可用”。

### 16.5 断点

#### 16.5.1 阻断后续的前置项

这些断点不满足时，后续旅程不能进入可用路径，不能当作“跳过”。

| 断点 | 被阻断的旅程与步骤 | 仍然可以做的事 | 恢复条件 |
| --- | --- | --- | --- |
| Agent 加入工作组织的审批不可用（Q06） | UJ05 第 2–3 步。乙的 Agent 因此不在甲的组织中，UJ08 中它与甲方的通信、UJ10 中迁到甲方组织机器的迁移都被阻断 | 查看成员、机器、拓扑（UJ09）；乙的 Agent 在已共享的组织中照常通信 | 审批可用并获批；或该 Agent 已有获准的归属 |
| 配置候选未被采信 | 依赖新配置的通信（UJ08） | 按已采信的旧版本继续；查看候选与差异 | 各节点 owner 采信 |
| 迁移目标方没有处理（目标端 GUI 或 R4.2 未就绪，或目标方未操作） | UJ10 第 5–7 步：开始与执行 | 源端查看迁移单与检查结果，可以取消迁移单；目标方随时可以打开请求并处理 | 目标方在 GUI 或 CLI 中同意，后端返回“可以开始”，源端刷新 |
| 所选空间的历史层异常（例如 `group-internal`，2026-10-29 实测） | 该空间的全部写操作（UJ07）；若异常的是配置空间，还包括 UJ06 第 3–4 步 | 预览内容；其他状态正常的空间不受影响 | 空间所有者重新发布后刷新 |
| 统计接口不可用 | UJ11 | — | 接口可用 |
| 删除组织 | UJ12 第 3 步 | 成员可以离开组织 | 后端修复 |

#### 16.5.2 可跳过的可选项

这些断点只影响单个步骤，旅程可以继续。

| 断点 | 影响的步骤 | 界面处理 | 旅程如何继续 |
| --- | --- | --- | --- |
| 当前组织（`org use`）未接通 | UJ02 第 2 步、UJ03 第 4 步 | 不显示“设为当前组织”的询问 | 新建 Agent 时手动选组织 |
