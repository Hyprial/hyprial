## 已有的地基（不需新建）

1. **Agent.agent_id 已存在**（`registry/_base.py:262`）：`a.` + base32(sha256("hyprial-agent-id-v1"+entityToken)[:16])，26 字符，匹配 `_AGENT_ID_SEGMENT = a\.[a-z2-7]{26}`。
   - 稳定性语义：entityToken 是 incarnation 级（"Opaque incarnation, regenerated by destructive rebuild/account transfer"）⇒ agent_id 在 **rename/display 变更下稳定**，destroy+recreate 换新 id（合理：那本来是新代理）。
   - ⚠️ 与 Allen 期望的差异点：若要求"跨 destroy/recreate 也保持 id"，则不能派生自 entityToken，需要独立列；默认按 incarnation 级设计，方案里作为决策点报 Allen。
2. **URI 文法 P1 已落地**（`kernel/impl/primitives/uri.py`）：`is_agent_id_segment` / `is_user_id_segment`(u.ou_*|u.uuid) / `is_device_id_segment`(d.hex32)。注释明言"P3 will use these same predicates while parsing address segments"——即本项目=实现既定设计的 P2/P3。
3. **名/id 无碰撞**：`registry.native_actor` 拒绝 id 形状的创建名（"agent name must not have an exact identity id shape"）⇒ a.xxx 段永不被当短名。

## 方案骨架（待细化报 Allen）

- P2: 注册表解析——parse 到 a.xxx 段 ⇒ 按 agent_id 解析到记录;短名段保持现状(双读);`uri_for` 双轨。
