## 2. Target design

### 2.1 Layout

```
gui/contract-mock/                 one module, both forms, runs under plain Node 24 (type stripping)
  index.ts        public surface; statically imports presets.json
  contract.ts     projectContract(openapi, envelope) -> table; selectors; canonicalJson; load-time checks
  schema.ts       JSON-Schema subset validator returning instance paths; throws on unknown keyword
  respond.ts      createContractMock: selection, presets, transitions, guards, envelopes, handle(), describe()
  browser.ts      createContractMockFetch: /daemon/session, /daemon/session/status, GET /daemon/request, POST /daemon/request/<m>
  serve.ts        Node form: startContractMockServer() and CLI
  presets.json    data: presets, transitions, inputGuards — references only, no payloads
gui/src/dev/contract-mock/
  index.ts        connectContractMock(selection), contractExamples(method)
  contract.generated.json   projectContract() output; byte-checked
gui/tests/contract-mock/           core, schema, presets, serve, conformance tests + synthetic.ts
contract/daemon-request/contract_mock/   __init__.py, contract.py (validation), envelope.py, sensitive.py, checks.py (new)
```

Rules for the module:
- Erasable TypeScript only (no enums, parameter properties or namespaces); relative imports end in `.ts`; `import type` for types.
- `gui/tsconfig.json`: add `"allowImportingTsExtensions": true` and `"contract-mock"` to `include`.
- No daemon method-name literal anywhere in `gui/contract-mock/*.ts` (gate rule).
- `gui/` is not under the 7-files / 1000-lines gate (`check_structural_limits.py:32-36` covers `src/hyprial`, `tests`, and line counts for `scripts`, `contract`, `sidecar`); the layout respects both anyway.
- `check:module-boundaries` resolves an import that leaves `gui/src` as a plain file and applies no rule to it (`check-module-boundaries.mjs:112-131,256-272`). So product code importing `gui/contract-mock` is caught by the new gate, not by that one.

### 2.4 `presets.json`

```json
{ "version": 1,
  "presets": { "success": { "scenario": "success" }, "empty": { "scenario": "empty" },
               "unconfigured": { "scenario": "unconfigured" }, "error": { "scenario": "error" } },
  "transitions": [],
  "inputGuards": [ { "method": "agent.provider.login",
      "requireOneOf": [ { "path": ["setupToken"], "equals": "example-not-a-credential" },
                        { "path": ["files", "*", "contentBase64"], "equals": "ZXhhbXBsZS1ub3QtYS1jcmVkZW50aWFs" } ],
      "refusal": { "code": "INVALID_ARGUMENT", "message": "mock login accepts only the documented synthetic sentinel" } } ] }
```

- A transition row is `{ "preset": A, "method": M, "next": B }`: after a 200 reply to `M` while preset `A` is current, the instance switches to `B`.
- `*` in a guard path means a non-empty array whose every element matches.
- At load, every method, case and preset reference must resolve, and the key set is exact.
- The interpreter is tested with synthetic tables. 1e-2 ships no real transition; stage F adds rows.

## 3. Conformance strategy

1. **Contract → JS** (`conformance.test.ts`, permanent, in `npm test`):
   - For every method and declared case, the Node form with `cases: {method: case}` and the case's params returns the declared result or error, the status from the map, and the right `dispatch`; `invalid-params` cases return 400 `not-dispatched`.
   - Every reply validates against `http-envelope.schema.json` `$defs.success` / `$defs.error`.
   - Every scenario × method without a case returns 409 with the recorded gap reason.
2. **Two forms agree** (same file):
   - Side N is the Node form behind the real `createDaemonRequestHost` with a real session. Side B is `createContractMockFetch`.
   - Probe table: `{}`, every case's params, one probe per selector, type and removal probes, an unknown key, an unknown method — for 4 scenarios and 3 override sets.
   - Equal `{status, envelope minus requestId, x-hyprial-catalog-digest}`; equal session payload minus `view/generation/csrf/expiresAt/requestId`; equal catalog document.
3. **JS = Python, once, before deletion** (`python-parity.test.ts`, exists only in commits 2–5):
   - The Python dump in Appendix A is piped into the JS core; `diff` must be 0.
   - The prototype result on `3db703124` is 4,102 rows, 0 differences.
   - Record in `docs/evidence/gui-contract-mock-js-parity-2026-11-15.md`: base SHA, row count, diff count, sha256 of the dump, sha256 of `openapi.json`. The dump itself is not committed.
4. **Red proofs:** comparator unit rows (altered result, altered status, missing header must each be reported); a deliberately wrong selection rule (last match wins) must fail the real table. The prototype measured 27 of 420 rows where replaying a case's own params selects a different case.

## Appendix B — reference algorithm (matched Python on 4,102 rows)

- **Validator.** `errors(schema, value, path, out)` walks the schema keys in order.
  - `properties`, `items` and a schema-valued `additionalProperties` descend with an extended path.
  - `allOf` and `then`/`else` descend with the same path.
  - `anyOf`, `oneOf`, `not`, `if` evaluate subschemas into a scratch list and report at the current path.
  - `integer` is `Number.isInteger`; lengths count code points (`[...s].length`); patterns use `new RegExp(p, 'u')`; equality is deep and insensitive to key order.
  - Annotations ignored: `description`, `examples`, `default`, `writeOnly`, `title`. Any other keyword throws.
- **First failing path.** Sort the paths element-wise; an equal prefix sorts the shorter path first. The message is `` `${method} params do not match the declared schema at ${path.join('/') || '<root>'}` ``.
- **Selectors.** Keys of `paramsSchema.properties` that also appear as a key of any `properties` object found anywhere in the result schema (walk every value, arrays included), minus `idempotencyKey` and `operationKey`.
- **Selection.** `candidates` = examples whose kind is in the scenario's kinds.
  - First candidate whose object params satisfy `key not in request || equal` for every declared key.
  - Otherwise first candidate satisfying `key not in request || equal || key not a selector`.
  - Otherwise 409: `MOCK_SCENARIO_MISSING` if `candidates` is empty, with message `` `${m} has no ${s} example (available: ${list || 'none'}).${gap ? ` Recorded reason: ${gap}.` : ''}` `` and the gap key map `{success: 'success', empty: 'empty', error: 'domainErrors'}`; else `MOCK_EXAMPLE_MISSING` with `` `${m} has no ${s} example that describes this request (selector fields: ${sorted.join(', ') || 'none'}); the Mock does not substitute another payload.` ``
- **Order in `handle`.** Unknown method (404 `METHOD_NOT_FOUND`, "unknown daemon method") → non-object params (400 `INVALID_ARGUMENT`, "params must be a JSON object") → input guard → schema → selection → error case (`dispatched`, status `statusByCode[code] ?? statusDefault`, `data` only when present) → success.
- **Envelope.** Every error message has `\r` and `\n` replaced by a space and is cut to 512 characters.
