# 首次设置固定 Pi + DeepSeek

决策 GUI-PI-FIRST-RUN-20261029。用户确认：当前首次设置只输入 DeepSeek API Key，默认 Pi，不提供账号授权/运行工具/服务商/模型/端点选择；高级配置留待配置页。

## 产品与瑞华交接
1. 第二页“配置模型”只提供 DeepSeek Key、输入框内显示/隐藏、单个主按钮“保存并继续”。文案：“首次使用默认通过 Pi 使用 DeepSeek，之后可在配置页调整。”
2. Key 成功保存后直接进入 Squire 步骤，不能叫“已连接”。恢复已有记录时显示“已保存 DeepSeek Key”和“继续”，提供次要“更换 Key”入口。Key 不写浏览器存储、不进 URL/命令行/日志，提交后清空。
3. 用户继续后自动准备 Squire：创建或核对已有实例→授予凭证→启动 Pi。进度和错误独立显示。
4. 已启动不等于模型可用。首次对话必须收到真实回复才确认首次设置完成，聊天尚未接通时明确不可用。
5. 运行工具（Pi/Codex/Claude Code）与服务商（DeepSeek等）是不同维度，不混在同一个选框。本次只做 Pi。

## 实现分层
GUI 私有 ModelStep/SquireStep 和状态编排；平台适配调用受限本机服务；本机服务只编排既有 CLI，不新增公共 daemon 接口或复制凭证实现。

只准固定操作：保存用户输入的单个 Key，查询 Squire 元数据，准备固定 Pi/DeepSeek 的 Squire，取消当前请求。路径、命令、actor、provider、model 均由可信宿主固定，不接受浏览器自定。

当前 CLI 能力：
- `agent secret provider-write` 从非 TTY stdin 接收值。
- `agent create --name squire ... --json` 原子保留新身份；重复名称即失败，不接管并发创建的实例。随后核对创建回执，以 `squire setup --json` 不加 `--start` 初始化该实例，当前默认 Pi/DeepSeek/deepseek-flash。
- `agent provider grant-key` 提供明确 agent 授权且不默认替换既有授权。
- `agent start pi --name squire --headless ... --json -- --approve` 发起启动；Pi P2 要求显式信任当前工作区，此参数不代表模型可用。

既有 Squire 必须先查：不同运行工具/服务商/模型或授权冲突时不覆盖、不停止。每次显式保存使用新条目，避免覆盖别处使用的旧 Key；仅保留条目/授权元数据，不在宿主缓存明文 Key。

本流程创建的实例通过持久化来源记录与实时 URI/创建时间核对后可继续。对其他已有实例，因公开 CLI 不足以完整确认授权，明确返回检查提示，不盲目改动。创建、授权、启动前核对同一实例；当前公开命令不能原子防御外部管理员在两个命令之间销毁重建实例，这一底层条件更新能力不在本轮 GUI 实现中。

## 本地开发启用

在认证预览环境基础上，可信启动端另设置 `HYPRIAL_GUI_SETUP=daemon`。宿主使用已配置的绝对路径 `HYPRIAL_GUI_AUTH_PYTHON` 与 `HYPRIAL_HOME` 启动固定动作 worker；worker 通过公共 `daemon_request` / `daemon_request_once` 调用 daemon，不执行 CLI 业务命令。页面不能自选方法、命令、路径或 home。未设置则初始化能力明确不可用，账号登录仍可使用。旧 `HYPRIAL_GUI_SETUP_CLI` 配置会被拒绝。

开发地址 `/src/features/dev01/onboarding/preview.html?auth=local`。此页账号和初始化是真实调用入口，未接通共享聊天，不应当作成品已完成验收。默认不带参数的 demo 仍不写真实配置。

## 验收与已知边界
测试使用 fake CLI 与临时目录，不保存真实 Key、不创建日常 Squire。验证保存→创建→授权→启动顺序、重试不重复创建、已有配置不覆盖、秘密不出现在 argv/响应/日志、实例 home/state 隔离、取消与迟到结果。

现有 CLI 尚未确认可完整列出 provider 授权记录，不能用 native secret metadata 列表冒充。非秘密检查点保存在所选 HYPRIAL_HOME 的 state/gui-first-run/pi-deepseek.json，仅记录条目 ID、实例 URI/创建时间、阶段与未决动作。刷新或服务重启后恢复保存状态，不读取 Key 回填。授权记录是历史事实，不等于当前有效授权；未知已有实例、身份变化或未决写入仍拒绝自动接管。

真实 DeepSeek Key、模型名可用性、Pi 载荷和真实回复需实测。单测通过或 start 返回成功都不能代替。原生 Tauri 由 Mini 继续接相同语义，当前 Web 接线不代表原生已经完成。

新增验证：`node --test gui/tests/setup-host.node.mjs`；`node gui/tests/auth-browser.mjs` 覆盖浏览器至本地服务的模拟保存/准备全链。测试永不写入真实凭证或启动日常 Squire。

## 模型步骤按钮简化（用户确认，2026-10-29）

新输入只保留一个主操作“保存并继续”，位于卡片右下；保存中显示“正在保存…”，禁止重复提交。只有保存成功才进入 Squire 步骤，失败留在本页。已保存记录只需“继续”，更换 Key 为次要操作；编辑取消保留原保存记录。输入框右侧显示/隐藏控件有可访问名称，默认隐藏，不改变其他凭证表单的布局。提示简化为“Key 将安全保存在当前实例中。下一步将准备 Squire。”
