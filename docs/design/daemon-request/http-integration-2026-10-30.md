## 范围：只有两个实现 PR

### H-01：真实 HTTP 入口与可用方法名单

- 复用 A 公共 request client、MethodSpec 与实际 handler 绑定。HTTP 层统一映射传输，不运行 CLI 子进程，不复制业务实现。
- 给出启动、就绪、关闭、查询目录和调用方法的公共方式。进程归属、认证、可信 principal 绑定及请求预算在准备阶段写清并经协调者审核。
- 运行时目录仅包含显式允许 HTTP、实际绑定且当前启用的方法。目录由同一声明来源投影，携带版本、参数、结果、错误、调用者要求、副作用、重试及确认元数据。
- 可用名单不等于无条件授权；每次请求仍需校验可信上下文及领域权限。body 中 actor/from 等业务字段不是身份凭证。
- 未迁移、内部、离线引导及未满足写操作协议的方法保持不暴露；无任意旧 router 回退。
- 统一限制来源、请求大小和错误泄露；写请求断线不盲重试。只在隔离本地环境验证，不发布公网服务、不读取生产凭据。

验收：真实隔离 daemon + HTTP 贯通 A 公开的 link 查询；非法参数、未知/未公开方法、伪造身份、未授权调用有拒绝证据；目录与实际入口逐项对应，故意制造漂移时测试变红。CLI、GUI fixture 均不是该验收的依赖。

### H-02：通用 TypeScript HTTP client 与消费交付

- 独立、可导入的 TS client：目录读取、按方法调用、既定凭据传递、预算/取消、类型化错误和版本检查。
- 不依赖 React 状态，不写账号/聊天/组织等页面控制器，不复制业务 schema 或手工维护方法白名单。
- 区分超时、传输失败与领域拒绝；不以客户端取消声称后端回滚，不自动重放结果未知的写请求。
- 交付使用说明、固定版本契约、独立消费者与真实调用例子；GUI/产品负责人负责之后逐功能接线。

验收：独立 TS 消费者通过真实 HTTP 调用真实隔离 daemon；覆盖错误、超时、断线、取消和版本不兼容；目录增加/移除方法时消费者行为明确。类型检查、单测、构建不能替代此实测。
