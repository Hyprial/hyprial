# GUI Init Track 任务登记

## 1. 目的

`intg/gui-init` 是 GUI 初始化阶段的公共集成分支。

4 条研发 track 和 1 条用户旅程分支必须从同一个集成版本开始。各分支独立开发、测试和审查，再通过 PR 合回 `intg/gui-init`。

任何人不得直接在 `intg/gui-init` 开发业务功能。共享文件、冲突处理和统一回归只由集成人负责。

模块边界和验收以冻结交接包的 `module-boundaries-r3.md` 与 `product-handoff-r3.md` 第 9 节为准。

唯一集成人是原网络 Developer（`work-developer`）。身份和职责依据 `shared-file-ownership-r1.md`。

## 2. 分支与负责人

| Track | 负责人 | 工作分支 | PR 目标 | 业务目标 |
| --- | --- | --- | --- | --- |
| dev-01 | 黄佳佳 | `feat/gui-dev-01` | `intg/gui-init` | 账号、首次使用、模型服务、本机初始化 |
| dev-02 | 林懿伦 | `feat/gui-dev-02` | `intg/gui-init` | Agent 创建、列表和管理 |
| dev-03 | 李震宇 | `feat/gui-dev-03` | `intg/gui-init` | 聊天、消息和飞书渠道 |
| dev-04 | 姚升悦 | `feat/gui-dev-04` | `intg/gui-init` | 组织、邀请和成员 |
| 用户旅程 | 陈瑞华 | `design/gui-user-journeys` | `intg/gui-init` | 补齐前两封邮件中的用户旅程页面与流程 |

仓库要求分支名使用 `feat/`、`design/`、`fix/` 等类型前缀。因此，工作分支不使用 `track/` 前缀。本文仍使用“track”表示 4 条业务线。

## 3. 共同规则

1. 开工前从最新 `intg/gui-init` 创建或更新工作分支。
2. 每条研发 track 只修改本业务线的私有组件、测试和说明。
3. 业务 track 不得直接修改共享外壳、全局状态、运行时、开发定位层、全局样式、共用测试或构建配置。
4. 需要共享能力时，先提交接口提案，由集成人修改共享文件。
5. 未接通真实后端时，页面只能显示“未连接”“状态未确认”或“暂不可用”。页面不得显示成功。
6. 每条 PR 必须独立测试和独立审查。PR 的目标分支必须是 `intg/gui-init`。
7. 一条 PR 合入后，其余分支必须同步最新 `intg/gui-init`，再继续开发或提交 PR。
8. `intg/gui-init` 完成统一回归前，不得合入长期分支。

## 4. dev-01：账号与首次使用

### 目标

交付账号入口、首次使用四步流程、模型服务配置和本机初始化。

### 包含范围

- 登录和注册入口。
- 首次使用流程：账号、模型服务、Squire、首次对话。
- 模型服务的账号授权与 API Key 两种配置方式。
- 模型额度、限制和费用说明。
- 本机初始化与设备身份创建。
- 正式构建无后端时的 `unavailable` 状态。

### 不包含范围

- Agent 创建和管理。
- 日常聊天和飞书渠道。
- 组织、邀请和成员管理。
- 全页面 `dev-XX` 配色。
- 最终组件和视觉精修。

### 依赖

- 前后端标准由黄佳佳确认并在可用后同步。
- dev-01 输出模型连接状态；集成人把该状态接入共享选择器。
- 用户旅程页面需要覆盖首次使用的进入条件、失败、重试和完成去向。

### 待办

- [ ] 登录和注册入口可用。
- [ ] 四步只能按顺序前进，Squire 不可跳过。
- [ ] 失败留在当前步骤，重试保留输入或选择。
- [ ] 首次对话成功后进入“开始”页。
- [ ] 设置页只保留账号、当前设备和普通偏好。
- [ ] 设置页不显示模型服务表单、Squire 创建、Squire 启动或“打开首次设置”入口。
- [ ] 连接页继续管理模型服务和消息连接。
- [ ] 开发模式不发真实业务请求，不写浏览器存储。
- [ ] 正式构建无后端时停在账号步骤，不显示成功。
- [ ] 375、760、1440 宽度无根横向溢出。

### 交付物与最低验收

- 独立提交、改动文件清单、测试和浏览器证据。
- 账号、模型、Squire、首次对话的正常、失败和不可用状态通过。
- 真实业务请求数为 0，`localStorage` 和 `sessionStorage` 写入数为 0。
- 完整 GUI 门禁通过。

## 5. dev-02：Agent 管理

- “管理 Agent”页面。

- 聊天消息发送。

### 依赖

- 消息渠道状态由 dev-03 提供。
- 林懿伦和姚升悦共同核对 demo request 的页面请求、接口响应和状态回写。
- 上述三步未通过时，页面必须显示未连接或暂不可用。

### 待办

- [ ] Agent 列表具备空状态和有数据状态。
- [ ] 搜索和筛选结果数与卡片数一致。
- [ ] 创建入口和详情页可进入。
- [ ] 管理页显示模型凭据和消息渠道两项状态。
- [ ] 未绑定模型凭据时显示“需绑定模型凭据”（hyprial 只有 agent / harness / model 三级概念，GUI 不使用“模型服务”一词）。
- [ ] 未连接渠道时显示“未连接渠道”。
- [ ] 状态未知时显示“状态未确认”。
- [ ] 未接后端的创建和管理动作不显示成功。

### 交付物与最低验收

- 独立提交、改动文件清单、状态截图和测试结果。
- Agent 状态只从共享选择器读取，不使用写死状态或示例数据推断。
- 创建和详情占位动作不发远端请求。
- 完整 GUI 门禁通过。

## 8. 用户旅程共享输入

`design/gui-user-journeys` 与 4 条研发 track 并行，但不修改 4 条业务线的状态机、适配器或后端契约。

陈瑞华负责：

- 补齐前两封邮件中的用户旅程页面。
- 明确入口、步骤、成功、失败、空状态和不可用状态。
- 标明页面之间的跳转和每一步的完成条件。
- 对照 4 条 track，标出页面归属和缺失接口。
- 在后端未接通时使用真实的未连接或暂不可用状态。

### 交付物与最低验收

- 前两封邮件涉及的页面清单，并标明页面归属、入口、完成条件和缺失接口。
- 账号与首次使用、Agent 管理、聊天与飞书、组织与邀请 4 条用户路径图。
- 每条路径覆盖成功、失败、空状态和不可用状态；未接通的流程不得显示成功。
- 页面跳转、返回路径和跨 track 依赖可判定，且不改 4 条业务线的状态机、适配器或后端契约。
- 独立 Reviewer 对精确提交给出通过结论。

用户旅程 PR 的目标同样是 `intg/gui-init`。该 PR 不应修改 4 条业务线的状态机、适配器或后端契约。

## 9. Demo request 请求流程

1. 林懿伦和姚升悦共同核对页面动作是否发出预期请求。
2. 两人核对接口是否返回可识别的成功或失败状态。
3. 两人核对页面是否按接口结果更新状态。
4. 三步通过后，记录接口、请求状态和失败合同。
5. 任一步未通过时，等待黄佳佳提供正在验证的前后端标准。
6. 标准也未就绪时，页面停在未连接、状态未确认或暂不可用。
7. 任何 track 都不得用本地成功状态冒充真实请求完成。

## 10. 共享文件与冲突

唯一集成人是原网络 Developer（`work-developer`）。4 条研发 track 和用户旅程分支向该角色提交接口提案与共享文件改动需求。

下列 4 个文件是已确认的冲突热点，只由集成人修改：

- `gui/src/App.tsx`
- `gui/src/app/AppShell.tsx`
- `gui/package.json`
- `gui/src/dev-mode/dev-module-index.css`

入口与外壳、全局状态、适配器和运行时只由集成人修改。

开发定位层、全局样式、共用测试和构建配置也只由集成人修改。业务 track 需要这些改动时，必须提交接口提案。

集成人负责：

- 核对每条 PR 的范围和共享文件改动。
- 处理冲突，不代替业务负责人决定业务行为。
- 每次合并后运行完整门禁。
- 维护 `intg/gui-init` 和统一预览。

## 11. PR 与合并流程

1. 负责人从最新 `intg/gui-init` 更新自己的工作分支。
2. 负责人完成本 track 的焦点测试和完整 GUI 门禁。
3. 独立 Reviewer 对精确提交给出通过结论。
4. 负责人创建 PR，目标分支设为 `intg/gui-init`。
5. 集成人核对范围、证据和冲突后合并。
6. 合并后，其他负责人同步最新 `intg/gui-init`。
7. Tester 在集成版本上完成跨 track 回归。
8. 陈瑞华检查用户体验、UI 和视觉。
9. 最终长期分支由后续明确决定，本阶段不得自行合入 `dev` 或其他长期分支。

## 12. 集成门禁

在 `gui/` 使用项目钉定的 Node 版本运行：

```sh
npm run verify
npm run verify:production-copy
npm run verify:safe-r1-browser
git diff --check
```

任一命令失败时，PR 不得合入 `intg/gui-init`。
