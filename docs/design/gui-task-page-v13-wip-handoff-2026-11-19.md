## 1. 目标

把 v13 PAC 任务页从独立样例摘出为可供研发查看的单文件原型，并用当前生产 GUI 的视觉规则重做外壳、卡片、表格、状态和详情抽屉。

本 PR 是 WIP 原型和交接文档，不把页面接入正式路由，也不代表任务数据已经接入真实 daemon。

## 2. 已保留的业务展示

- 任务列表；
- 搜索任务；
- 分别按工作项状态、PAC 状态和关联关系筛选；
- “本人可处理”提醒区；
- 工作项状态、PAC 总体状态和按依赖层分段的步骤进度；
- 任务详情抽屉；
- 详情抽屉平铺工作项概览和步骤依赖；
- 依赖图、步骤选择和步骤输出；
- 固定脱敏样例数据及原有字段语义。

## 3. 视觉调整

- 使用 4183 的浅色页面背景、黑色侧栏、白色卡片、浅绿主色和语义状态色。
- 使用 dev GUI 的 Geist / Noto Sans SC 字体栈和 20px 卡片圆角。
- 任务列表使用生产风格的搜索框、筛选器、状态徽章和表格行悬浮态。
- 详情抽屉使用生产风格的事实卡片、步骤图和输出块。
- 保留窄屏下的单列布局和任务详情滚动行为。

## 4. 开发边界

允许的下一步：

- 把任务页拆分为 `gui/src/pages`、`gui/src/features` 和共享 primitives；
- 将静态样例替换为真实 capability 和 daemon request；
- 为列表、详情和步骤补充组件测试与浏览器测试；
- 保留 loading、empty、error、unknown 和只读状态的真实语义。

本 WIP 不包含：

- 正式路由接入；
- 新增 HTTP 路由、数据库或凭据存储；
- 修改 PAC、任务、步骤或输出字段契约；
- 把示例数据当作真实任务执行结果；
- 修改旧 `src/gui` 或原生壳页面。

## 5. 验收标准

1. 原型可由浏览器直接打开，任务列表和详情抽屉可用。
2. 搜索、三组筛选器、任务详情、步骤选择保持可操作。
3. 视觉使用 `gui/src/styles/themes/hyprial-v5.css` 的颜色和字体语义。
4. 桌面和窄屏布局不出现横向溢出。
5. 示例数据与真实后端能力明确区分。
6. 研发可以按第 4 节拆分正式组件，不需要复制旧样例的页面外壳。

## 6. 当前限制

- 当前原型只使用内联脱敏样例数据。
- 当前原型尚未接入正式 GUI 路由。
- 当前尚未运行真实 daemon 任务读取、任务刷新或任务执行验证。
- 正式实现前需要产品确认任务权限、刷新策略、错误重试和任务执行动作。
- 当前原型不展示清单完成数、文字依赖清单、本地用户可完成标记和内部引用字段。
