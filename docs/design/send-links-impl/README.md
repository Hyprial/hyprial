## 缝的裁定（集成者，依据设计文档；超出设计的另列）

来自 WP1 设计节点的建议，逐条裁定，评审与实施节点以此为准：

1. `LinkState` 保留为 ports 里的 Literal；节点视图数据类命名 `NodeView`，放 policy.py。
2. 放弃阈值的回退：该 link 无 RTT 样本时取 4 倍本节点 T_max。已写进设计 §5.1。
3. 样本分两类喂控制器：本节点发出的回复（给 W）与某条 link 上收到的回复（给该 link 的 cwnd）。WP2 必须分开上报。
4. 设计未定的常数按下列默认值进 `ControllerConstants`：周期抖动比例 0.1、平滑增益 0.125、link 最短存活期 1 个周期、抖动判定为一个周期内回收数超过 k。
5. `Mint` 增加 `evict: str | None = None`，由 policy 选定淘汰对象，store 不再二次选择。已改 ports.py（加性字段）。
6. 不增加 `Refuse` 决策变体。拒绝一律以 kernel 的 `DaemonRequestError` 抛出（LINK_UNKNOWN、LINK_RECLAIMED、SUMMARY_REQUIRED、MESSAGE_REPLY_UNAVAILABLE），`SendDecision` 保持 Allow | Mint | Hold。WP3、WP4、WP6 据此只处理三种决策加异常。
7. PAC 任务绑定的 link 不计入 k，但其在途请求计入 cwnd 与 W。理由同 R6：派单者对 worker 的关系与 owner 对 agent 的关系同构，且 worker 结束即释放。这是对设计 §3.2 的扩展，待 Allen 确认；在他确认前按此实施。
