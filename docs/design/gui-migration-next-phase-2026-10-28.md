## 3. 架构与职责边界

```text
gui/ 页面与组件 → 状态／前端适配层 → 已约定的调用边界 → daemon request → daemon
                  ↑
          网页与原生壳使用同一GUI

clients/native/       原生壳、平台能力、所属进程生命周期
packaging/clients/    载荷准备、压缩校验、安装与分发
src/hyprial/         公共CLI/daemon实现，独立后端PR审核
```

- `hyprial gui` 保持浏览器网页形式；dev-mode 保持独立工作树和热更新。
- 桌面包自包含 Python、Node、CLI/daemon、Pi、sidecar 等所需运行环境，与外部 CLI 安装隔离；不能依赖开发机全局环境来掩盖缺载荷。
- 移动端是授权会话入口，不携带桌面 daemon/Pi 运行时，不因迁移五端而改变该边界。
- 旧 Core 页面、旧登录页、原型 HTML 直包入口不作为第二套页面恢复；能力接入共享 GUI。
- 状态以真实后端为准。模拟数据、占位响应、未知结果明确区分；不以 ACK 代替业务完成。
