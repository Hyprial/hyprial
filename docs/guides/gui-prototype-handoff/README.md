# GUI 原型交接规范

版本：1.1（2026-10-24）。面向产品负责人瑞华、原型实现 agent 与 GUI 接入方。

> **现行交付路径提示（2026-10-28）**
>
> 本目录的“原型 HTML 直接打包进客户端”交付路径已由**组件化 `gui/` + `hyprial gui` / `hyprial gui dev` 开发预览**取代。新页面研发必须以仓库根 `gui/` 的 React + TypeScript + Vite 实现为唯一主线，不再以原型直包作为正式客户端页面，也不长期维护原型与正式页面的双实现。
>
> 本目录中仍然有效的规则继续适用：瑞华统一负责产品设计与交互；研发可为解除阻塞先补 UI，但必须明确标记、按 DEV-UI 登记并交回产品统一；演示数据必须显著标识，演示/live 隔离；没有真实接口时不得伪造成功、在线、登录、发送或回复；验收必须区分视觉、fixture、真实业务、原生安装和真机认证。
>
> 新流程、组件、状态、无障碍和交接要求以 [GUI 设计与研发规范](../../../gui/docs/ui-development-standard.zh-CN.md) 为准，并配合 [组件目录](../../../gui/docs/component-catalog.zh-CN.md) 与 [UI 变更交接模板](../../../gui/docs/ui-change-handoff-template.zh-CN.md)。下方 1.1 内容保留为历史交接证据；其中与组件化主线冲突的直包步骤不再作为当前实施指令。

## 从这里开始

1. [MVP 必要流程与页面补齐](mvp-required-flows.md)：M1–M5 定义用户路径、页面缺口、状态及验收；本轮优先模型凭证 → 校验 → Squire → 聊天。
2. [原型交付与 Agent 实施规范](prototype-contract.md)：N1–N8 定义所有权、稳定 hooks、demo/live 隔离、平台能力、交付包和自检。
3. [变更记录](CHANGELOG.md)：规范变更、兼容性及版本追溯。

本文档是产品需求与交付约定，不宣称后端能力已实现，也不替代运行时的安全授权。瑞华维护原型视觉与交互，接入方维护桥接、CLI/服务能力、凭证存储、平台适配与原生验收。

## 研发 UI 补齐例外

当原型缺失或阻塞功能时，研发可先补表单、按钮、提示及必要交互，标注并记录，后续集中交瑞华统一设计。无需为每项等待产品批准；保留原件、遵守真实能力和安全边界，并最终收敛补丁。详见 [实施规范 N1.1](prototype-contract.md#n11研发先补产品后续统一设计)。

## Git 与 Hyprial 的分工

Git 是版本依据；Hyprial 负责交接通知、问题协调与回执。聊天附件可作为讨论快照，不能静默覆盖已入库规范。交接消息包含仓库/PR 链接、精确 commit、需求编号、本次差异和待确认项，不携带凭证或邀请秘密。

规范更新通过文档 PR；原型更新通过独立原型 PR，原件及本地资产、DELIVERY.md、动作变化表和无秘密 fixture 一并提交。原型在 `gui/prototype/vendor/fisher/<version>/` 版本化归档（该目录随 GUI 实现分支交付；本纯文档 PR 不新增产品目录）。接入方记录原件 SHA256、桥接版本、产品 commit 和包来源，不把文件名当唯一版本证据。

确认分层记录：提交/消息受理 → 对方实读及问题反馈 → 原型交付 → 桥接验证 → 各端真实验收。消息送达不等于认可，原型演示通过不等于产品通过。

## 更新兼容性

需求沿用 M1–M5，规范沿用 N1–N8，已有编号不换义。纯文案和视觉调整保持动作语义；删除动作、变更参数/状态含义或版本协商规则时必须列出兼容影响，并由接入方同步更新。未实现接口标待对齐，不由任一侧单独宣布生效。

代码 PR 目标遵循该开发线规则；目标 dev 的合入由 gui-verifier 独立审核并执行，满足服务器实际保护及适用 CI。不得把规范入库等同原型发布、客户端发布或权限变更。
