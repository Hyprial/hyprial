# MVP 必要流程与页面补齐

交接给：产品瑞华及其原型实现 agent。更新：2026-10-24。
本文是下一版原型的产品需求与验收依据，不是“功能已经实现”的声明。以 v15 接入调查为起点；已经具备的页面保留，只补缺失入口、状态和数据接入点。视觉与交互设计由瑞华负责，真实 CLI/服务调用、凭证保存、平台适配和安装包由 GUI 接入方负责。

## 这次要解决什么

让第一次安装的用户，无需开发者代填配置，就能配置模型、启动 Squire 并完成真实聊天。当前最直接的缺口是：原型有模型服务展示和演示配置流程，但缺少可接真实服务的凭证输入。没有凭证，模型无法调用，不能把“添加成功”当作“可以聊天”。

交付优先级：先完成 M1–M3（本地聊天），再补齐 M4–M5（远端通讯和一致的状态反馈）。不要求一次实现所有 Agent 管理、任务编辑、飞书配置等页面。

## 缺口阻塞研发时怎么办

GUI 研发线可以先实现 M1–M5 中缺失或阻塞的 UI，不用等待瑞华出新版。新增入口标记为“研发补齐，待产品规范设计”，连同 PR、截图、动作接口和验收结果登记，按迭代集中交接瑞华。瑞华后续统一设计，接入方回归验证并收敛临时补丁。具体操作见 [N1.1](prototype-contract.md#n11研发先补产品后续统一设计)。

## 用户应能走通的两条路径

**桌面本地聊天：**打开客户端 → 查看当前实例状态 → 配置模型凭证 → 校验模型 → 创建并启动 Squire → 进入聊天 → 发消息并看到真实回复。

**远端聊天：**完成账号登录与设备配置 → 查看可访问节点/Agent → 必要时创建或加入组织 → 选择 Agent → 建立会话 → 收发消息及恢复历史。

这两条路径不是强制串行。未加入组织不能阻止本地聊天；账号登录、设备配置、网络可达、模型可用、Squire 在线也不能合并成一个“已连接”。桌面安装包与外部 CLI 是独立实例，页面不能默认继承外部登录或凭证。

## M1｜模型凭证输入：本轮第一优先级

**用户入口**：首次设置中的“配置模型”；日常“连接 → 模型服务 → 配置/更换凭证”。无模型时提供明确按钮，不只展示空列表。

**页面内容**：
- 服务商、模型：展示宿主返回的可选项；本轮先跑通 DeepSeek，不能把 UI 中任意填入的模型名称视为后端已支持。
- API Key：密码输入框，可粘贴，可短暂显示/隐藏。说明“用于当前桌面实例的模型服务”。
- 操作：保存凭证、校验模型、修改/更换凭证。允许做成“保存并校验”，但仍分别显示两步结果。
- 已保存后只显示“已配置”，不回显或重新填充原 Key。不要为演示预置任何真实 Key。
- 自定义服务地址不是本轮必填项；只有后端提供该能力时才展示，避免错误域名导致凭证外发。

**需要设计的状态**：未配置 → 保存中 → 已保存、待校验 → 校验中 → 可用；以及保存失败、凭证无效、余额/额度不足、网络超时、模型不可用。不确定的失败显示后端提供的可读原因，不统一写成“Key 错误”。校验可能调用模型并产生少量用量，按钮附近简短说明。

**给 agent 的实施约束**：Key 只在输入控件及一次提交过程短暂存在，经过专用敏感字段通道交宿主。不得进入普通页面 state、data 属性、URL、浏览器持久存储、日志、分析上报或截图测试数据。提交后、取消或离开表单时清空控件；保存失败需要重填时明确提示。清空只是减少保留，不能声称 JavaScript 已保证内存擦除。真正存储和密钥管理由宿主负责。

**验收**：空 Key 不发请求；保存失败不显示成功；保存成功但校验失败不显示模型可用；校验成功才进入下一步；重开页面可看到已配置状态但看不到 Key；更换失败时页面根据后端结果展示旧配置是否仍有效，不自行猜测。

## M2｜启动 Squire：让用户知道还缺哪一步

**用户入口**：模型校验成功后显示“启动 Squire”；日常页面保留“查看状态/重试启动”。首次设置只创建 Squire，不安装 default agent。

**状态**：未创建、启动中、在线、离线、启动失败。缺模型配置时提供返回 M1 的入口；已经存在时复用，不因反复点击或应用重启重复创建。

**验收**：模型可用不等于 Squire 在线；只有宿主确认实际运行才显示在线。失败后保留具体原因及重试入口。按钮请求中防重复点击。已有 Squire 再次进入设置不会增加第二个 Squire。

## M3｜聊天闭环：消息真的收到了才算完成

**页面必须具备**：目标节点/Agent、会话列表、消息记录、输入框、发送状态、错误提示、刷新或自动更新入口。历史较长时提供加载更多；若后端暂不支持，明确当前展示范围。

**状态必须区分**：正在发送、服务已受理、发送失败、结果待确认、已收到回复。服务受理不能显示为“Agent 已读”或“已回复”；不得用定时器生成假回复。超时结果不明时保留草稿并提示核对，重试由接入层按同一消息标识处理，页面不能盲目反复发送。

**验收**：不切页面也能看到新回复；网络断开有提示，恢复后刷新历史；同一消息不重复展示；重新打开会话仍可读取历史；消息时间来自真实时间戳，不一律写“刚刚”。消息中的 HTML/脚本作为文本显示。

## M4｜账号、节点与可选组织：远端聊天的入口

**页面入口**：登录/查看当前账号；设备配置及失败重试；可访问节点/Agent 列表；创建组织、加入组织或接受邀请入口（仅在宿主支持时启用）。邀请材料按敏感内容处理，不进入日志或分享截图。

**产品要求**：无组织、尚无可访问节点、正在发现、网络故障、无权限、接口未支持分别说明。组织可跳过，不能将它作为本地 Squire 的启动条件；加入组织也不等于已证明网络可达。所有列表必须来自当前实例真实数据，不展示示例在线节点。

**验收**：没有组织仍能走 M1–M3 本地路径；远端列表为空能知道原因及下一步；选中某 Agent 后会话目标保持一致；登录成功但设备配置失败时显示两者不同状态。

## M5｜所有关键页面都有错误与能力提示

聊天、通讯录、首次设置、模型服务都应提供统一的页内提示位置。按钮不可用时说明缺少什么，以及可执行的下一步。页面允许保留尚未接入的功能，但要禁用并标明原因，不能点击后展示演示成功。

诊断编号可以复制，原始堆栈、内部路径、协议术语不作为主要用户说明。未知状态显示“状态暂不可用”，不要编成“离线”或“连接失败”。

## 平台差异：共享页面，不能共用错误的能力假设

| 平台 | 模型与 Squire | 网络与会话 |
| --- | --- | --- |
| Windows/macOS/Linux 桌面包 | 本实例模型凭证入口；本实例 Squire | 本地聊天及获授权的远端会话；与外部 CLI 隔离 |
| Web（hyprial gui） | 取决于当前 CLI 实例提供的能力和授权 | 连接启动它的 CLI 实例；不要固定展示桌面安装流程 |
| iOS/Android | 不创建本地 Squire/daemon，不要求输入远端主机模型 Key | App 内 tailnet + 正式登录/设备授权，访问获授权主机的会话入口 |

移动端需保留窄屏、安全区和键盘弹出后的输入/发送可见性。远端主机模型未就绪时提示该主机负责人处理，不把主机凭证索取转嫁给移动用户。

## 双方如何交付和验收

瑞华交付上述入口、状态及稳定 hooks；原型 agent 用非秘密 fixture 覆盖正常、空、加载、失败、无权限和不支持场景。GUI 接入方提供真实能力、状态、调用结果并完成原生端测试。

验收分开记录：①原型流程完整；②桥接可调用；③真实模型/Squire/聊天通过。只通过演示交互或截图，不能记为③。

本轮不要求瑞华处理凭证存储、daemon、网络协议、CI 或打包问题；这些由接入方承担。后端缺能力时双方登记缺口，不要求原型伪造能力。
