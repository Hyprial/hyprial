# zen-hyprial：表达什么

本 skill 管**内容与结构**。措辞交给 stc（中文）或 ste100（英文）。

与另两个 skill 的分工：

```
comm-type     判断这是哪一类沟通，只输出标签
zen-hyprial   按标签给出骨架：必须包含哪几块（本文件）
stc / ste100  如何用中文或英文把这个骨架写成句子
```

## 第一步：先拿到类型

不得自行判类型。用 comm-type，拿一个标签。没有标签时先判，不得猜骨架。

## 第二步：按类型取骨架

七个类型，每类一个必须包含的块清单。缺块即不合格。

### ask 请对方回答

```
必须含：目标链 / 查过什么 / 最小可复现输入 / 约束 / 不确定性许可
```

- 目标链：`小目标 → 大目标`。只给小目标时，对方无法判断该不该这样做。
- 查过什么：三项齐全——查过什么、结论是什么、为什么不能用。
- 最小可复现输入：能单独跑起来的最小那份。是删减版时写清删了什么。
- 约束：写成 `不能用 X，因为 Y`。
- 不确定性许可：一句“不确定的请标出来，不得跳过”。缺这句时，对方遇到答不出的题会静默跳过。

不得：只描述自己的方案再问该方案行不行。要问方案时另给一句“不限定 X 的话，达到 Y 还有别的办法吗”。

### decide 请对方裁决

```
必须含：要决定什么 / 选项及各自代价 / 我倾向哪个及理由 / 不决定的后果与时限
```

不得：把决定包装成倾向。写成“宜 A”时，对方无法知道这是他该定还是我已定。

### tell 只告知

```
必须含：发生了什么 / 影响谁 / 是否需要对方动作（要就写“不需要”）
```

不得：留开放结尾（“有问题随时说”）。那会把 tell 变成 ask。

### report 汇报进度

```
必须含：结论先行 / 三档状态 + 证据 / 未覆盖范围 / 卡住的事
```

- 三档状态只能是 `已完成`、`进行中`、`受阻`，每档附一条能复算的证据。
- 未覆盖范围写“无”也要写。
- 卡住的事写“无”也要写。

不得：按时间顺序讲经过。时间顺序是默认形态，而它是错的。

### hand_over 交底

```
必须含：交给谁 / 交出去的事实清单（带 as_of）/ 我做到哪、没做到哪 / 之后找谁
```

不得：只说“后续由你负责”。那会把已确认的事实一起丢掉。

### refuse 拒绝或撤回

```
必须含：关闭的是哪条路 / 为什么关 / 已经受影响的产物怎么处置 / 它误伤了什么
```

不得：只写“不行”。撤回时必须写“它误伤了什么”，否则下一次没人知道该不该重试。

### incident 事故通报

```
必须含：现象（可观测的）/ 已确认与未确认分开 / 影响面 / 现在要对方做什么或不做什么
```

不得：把“未观测”写成“已观测为否”。两者不同形。

## 第三步：交付前自查

```
四问，任一答否即不合格：
1 这个类型的必须块，是否齐了
2 有没有把 X 问题写成 Y 问题的结论（Y = 解决 X 过程中采用的特殊方法带来的问题）
3 待对方做的事，是否单独列出来了
4 未覆盖范围，是否写了（写“无”也算写了）
```

## 与其他 skill 的边界

```
本 skill 不判断语言风格、不用词、句子长度 —— 那是 stc / ste100 的事
本 skill 不判断该不该发 —— 那是发出方的事
本 skill 不保证内容正确 —— 只保证该说的块都在
```
